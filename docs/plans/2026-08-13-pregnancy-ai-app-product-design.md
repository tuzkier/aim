# 孕期 AI Agent App 产品总方案

## 1. 项目定位

本项目是一款以孕期为首期范围、未来延伸至孩子 3 岁的家庭成长陪伴 App。

它不是单纯的母婴问答产品，也不是待办工具附加一个聊天助手。产品本体由计划、待办、日历、档案、记录、报告、提醒、家庭协作、本地事务和服务选择等完整功能构成；不同领域的专业 Agent 贯穿所有功能，持续理解家庭状态、制定行动方案、调用功能完成事情并追踪结果。

产品可以概括为：

> 多功能母婴 App 是身体，专业 Agent 团队是贯穿全局的大脑；每个 App 功能同时也是 Agent 可以调用的 Tool。

首期面向中国大陆家庭，优先服务实际生活在浙江杭州的家庭。首期聚焦孕期，从确认怀孕持续到分娩住院、出院及产后最初几天的自然交接。

## 2. 核心用户价值

孕期家庭不需要自行研究所有知识、记住所有节点、协调所有人员和判断下一步行动。App 持续回答并处理四类问题：

1. 家庭目前处于什么阶段，发生了什么变化；
2. 现在、今天和接下来一段时间应该做什么；
3. 这些事情该怎么做、由谁负责、什么算完成；
4. 哪些事情 Agent 可以直接处理，哪些需要用户、医生或专业服务介入。

产品最终交付的不是一段建议，而是被写入 App 并持续追踪的计划、任务、记录、提醒、材料清单、家庭分工和后续行动。

## 3. 长期产品边界

长期产品覆盖从确认怀孕到孩子满 3 岁的完整家庭生命周期，同时维护三条连续时间线：

- 妈妈线：孕期健康、分娩、产后恢复、情绪、工作与个人生活；
- 孩子线：健康、喂养、睡眠、发育、早教与社会适应；
- 家庭线：分工、办事、物品、消费、服务选择和家庭关系。

长期生命周期分为：确认怀孕与孕早期、孕中期、孕晚期、分娩与住院、产褥期与新生儿期、宝宝 1～3 个月、4～6 个月、7～12 个月、1～2 岁、2～3 岁。

阶段不是机械切换。生产方式、早产、疾病、喂养选择、妈妈复工等事件会改变计划与活跃 Agent。

## 4. 首期产品范围

首期只做孕期，但不是单一聊天体验或浅层功能集合，而是一套能够正式使用的完整孕期产品。

### 4.1 生命周期范围

- 确认怀孕与孕早期；
- 孕中期；
- 孕晚期；
- 分娩准备；
- 分娩住院、出院及产后最初几天的自然交接。

### 4.2 业务范围

- 孕周识别与阶段管理；
- 产检、建册、建档和报告管理；
- 健康、营养、运动、睡眠和情绪管理；
- 症状、体重、胎动、宫缩等记录与工具；
- 待产包、分娩准备和家庭分工；
- 杭州本地医院、社区服务、补贴与办事事项；
- 孕期用品采购、月嫂、产康及其他专业服务选择；
- 分娩住院与产后最初几天的交接计划。

育儿期的喂养、宝宝睡眠、成长发育和早教等能力不作为首期主体，但产品长期叙事保留向产后和 3 岁延续的方向。

## 5. 完整功能版图

以下能力既是用户可以直接操作的功能，也是 Agent 可以调用的 Tools。

### 5.1 阶段与计划

阶段目标、今日事项、待办、日历、提醒、任务依赖、任务分工、阶段复盘和下一阶段准备。

### 5.2 健康与医疗

家庭健康档案、产检计划、报告管理、就医记录、用药记录、指标趋势、风险提醒和问诊准备。

### 5.3 日常照护与记录

孕期症状、体重、饮食、运动、睡眠、情绪、胎动、宫缩等记录，以及对应的快捷工具。

### 5.4 知识与行动方案

围绕当前阶段和真实问题提供可信知识，并转化成行动步骤、观察指标、任务、提醒和后续追踪，而不是提供文章列表。

### 5.5 家庭协作

家庭成员、照护权限、任务分工、共享提醒、伴侣支持、重要信息同步和分娩期间的协作安排。

### 5.6 本地事务与权益

杭州地区的建册建档、医院与社区服务、补贴、医保、证件、政策时限和办理材料管理。

### 5.7 用品与专业服务

用品清单、预算、购买决策和准备进度，以及医院、月嫂、产康等服务的发现、比较和安排。

### 5.8 成长记忆

孕期照片、重要时刻、检查节点、家庭记录和阶段总结，并形成连续的家庭时间线。

社区、用户讨论和同城交流不属于产品首期核心范围。

## 6. Agent 团队

Agent 按长期专业责任划分，而不是按页面或功能按钮划分。首期包含：

1. **成长规划 Agent**：负责全局调度、阶段目标、主责分派、冲突仲裁、计划统一和结果汇总；
2. **孕产 Agent**：负责孕期、产检、待产、分娩和产后最初几天的衔接；
3. **妈妈照护 Agent**：负责身体状态、情绪、睡眠、运动、工作与个人生活；
4. **健康就医 Agent**：负责检查报告、症状、就医准备、医嘱追踪和风险升级，但不替代医生诊断；
5. **营养 Agent**：负责饮食、营养、体重变化及相关行动计划；
6. **家庭协作 Agent**：负责伴侣和其他家庭成员的任务分工、支持与交接；
7. **杭州生活事务 Agent**：负责本地政策、机构、权益、用品和专业服务事项。

不同 Agent 具有各自领域的专业 Skills。现阶段先由项目逐个建设完整专家能力，不建设 Skill 生态，也不讨论外部发布机制。

## 7. 多 Agent 协作原则

多 Agent 不平行面向用户各自给出结论。核心规则是：

> 多个专家参与判断，但每件事只有一个主责 Agent，最终只形成一份统一方案。

- 成长规划 Agent 负责分派、协调、冲突仲裁和统一计划；
- 每个问题只能有一个主责 Agent，其他 Agent 提供协作判断；
- Agent 之间的会诊默认在后台完成；
- 家庭始终只有一套日历、待办、健康档案和阶段计划；
- 冲突不能被静默掩盖，医疗安全优先，无法可靠判断时交由用户或专业人员决定；
- 用户可以直接进入某个 Agent，但跨领域问题仍通过后台协作形成统一结果。

## 8. Agent 与 Tool 的关系

产品采用同一套能力、两种使用方式：用户可以直接操作功能，Agent 也能调用这些功能替用户处理事情。

典型运行过程为：

> 获取家庭状态 → 判断问题 → 选择主责 Agent → 多 Agent 协作 → 形成统一行动 → 调用 Tools → 更新家庭状态 → 持续追踪

例如上传产检报告后，健康就医 Agent 读取并整理报告，孕产 Agent 判断对当前计划的影响，营养 Agent 提供相关判断，成长规划 Agent 统一更新任务优先级，最终写入健康档案、待办、日历和提醒。

每个 Tool 都需要形成完整操作闭环。例如待办 Tool 不只是创建任务，还应支持查询、拆解、排期、分配、提醒、完成、延期、复盘和撤销。

## 9. App 信息架构

底部设置五个一级入口：

### 9.1 今天

总控首页。展示当前孕周与阶段、今天最重要的事情、近期任务、需要关注的变化、Agent 已处理事项和快捷记录。

### 9.2 计划

承载孕期时间线、阶段目标、待办、日历、家庭分工和整体进度。

### 9.3 记录

集中管理健康、医疗和日常数据，并根据孕期阶段动态展示常用记录工具。

### 9.4 Agent 团队

展示当前主责 Agent、活跃专家、最近协作结果和历史对话。用户既可以直接找某个 Agent，也可以将问题交给团队。

### 9.5 家庭

管理妈妈、伴侣和其他照护者的档案、权限、分工、服务、用品、权益与孕期记忆。

产品同时提供全局 Agent 入口。用户在任何页面都可以发出指令、上传资料、针对当前页面请求处理或查看 Agent 正在进行的工作。

首页不以聊天框为中心，而以家庭状态和下一步行动为中心。

## 10. Agent 主动运行机制

Agent 在用户不开口时也持续工作，主要由以下变化触发：

- 时间变化：进入新孕周、产检临近、政策时限或阶段切换；
- 数据变化：上传报告、记录体重、症状、胎动等数据；
- 行为变化：任务反复延期、长期未记录、计划难以执行；
- 外部变化：杭州政策、医院服务或重要公共信息变化。

主动运行形成连续循环：

> 观察家庭状态 → 识别变化 → 协作判断 → 更新计划或执行 Tool → 告知用户 → 追踪结果

执行权限分为三档：

- 直接执行：创建和调整普通待办、生成清单、整理记录、形成总结；
- 执行后告知且可撤销：重新排期、调整优先级、分配普通家庭事项；
- 执行前确认：医疗处置、用药、付费、购买、预约、取消服务、隐私分享及不可逆操作。

主动不等于增加通知。用户主要看到今天需要关注什么、Agent 已经处理什么、哪些事情需要决定、哪些风险必须立即处理。

## 11. 杭州本地化

杭州本地化嵌入生命周期和任务系统，而不是一个独立资料频道。

产品需要了解家庭的实际居住区、户籍所在地、医保与就业状态、建册建档情况、就诊医院、社区卫生服务机构和家庭照护资源。

杭州本地能力包括：

- 建册建档、产前筛查、产检和分娩机构；
- 医院、妇幼保健机构和社区服务；
- 孕产补贴、生育待遇及其他家庭权益；
- 分娩前后需要准备的本地事务与材料；
- 月嫂、产康及其他专业服务选择；
- 根据杭州季节、居住条件和预算生成用品建议。

本地事项进入家庭统一计划，与健康、待产和家庭协作事项共同编排。所有地域信息应记录来源、适用范围和更新时间；无法确认的规则只提供核实入口，不将推测作为确定结论。

## 12. 产品成功标准

首期产品不以页面数量或聊天轮次验收，而以家庭能否完成以下闭环为核心：

> 了解家庭 → 建立完整孕期计划 → 主动推进 → 调用功能完成事情 → 根据新信息调整 → 跟踪结果 → 顺利衔接分娩与产后最初几天

用户应明显减少自行搜索、记忆节点、整理材料、协调家人和反复组织问题的负担，同时能够清楚知道 Agent 做了什么、为什么做、哪些事项需要自己决定。

## 13. 当前决策与下一阶段

当前已确认：

- 产品是完整多功能 App，而不是对话产品；
- 每项功能既服务用户，也是 Agent 的 Tool；
- 多个专业 Agent 长期存在，并通过成长规划 Agent 统一协作；
- Agent 可以大胆主动执行普通事务，但关键事项保留确认；
- 首期面向杭州家庭并只做孕期；
- 首期终点包含分娩住院、出院及产后最初几天的自然交接；
- 暂不建设社区、Skill 生态和跨城市扩展方案。

项目总方案确认后，下一阶段应从首期孕期范围继续拆解：完整孕期用户旅程、首期功能结构、各 Agent 职责与 Skills、关键场景闭环、产品原型与实施计划。

完整孕期用户旅程已在《孕期 AI Agent App 完整用户旅程》中进一步定义，下一阶段进入首期功能结构梳理。

整体系统边界和关键技术决策已在《孕期 AI Agent App 整体架构方案》中定义。功能结构应在该架构边界内继续展开。
