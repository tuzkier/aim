# 孕期 AI Agent App 完整用户旅程

## 1. 文档目的

本文档承接《孕期 AI Agent App 产品总方案》，描述首期产品从用户加入到分娩、住院、出院及产后最初几天交接的完整用户旅程。

本阶段只定义用户处境、阶段目标、关键事件、产品介入与阶段交接，不展开具体页面、单个 Agent 的详细 Skills 或技术实现。

## 2. 用户旅程设计原则

### 2.1 用户可以在任何孕周加入

产品不要求用户从刚确认怀孕时开始使用。无论用户处于孕早期、孕中期还是孕晚期，Agent 都应先识别当前阶段和紧迫事项，再还原已经完成、正在进行和可能遗漏的事情。

### 2.2 先建立可用计划，再逐步补全信息

首次使用不要求一次填写完整档案。产品先根据少量关键信息生成当前可执行的孕期计划，再在后续服务、记录和资料上传过程中逐渐补全家庭上下文。

### 2.3 每个阶段形成完整行动闭环

每段旅程均包含：

1. 家庭当前处境；
2. 本阶段核心目标；
3. 关键事件和需要完成的事情；
4. App 提供的功能支持；
5. 主责 Agent 与协作 Agent；
6. Agent 应主动采取的行动；
7. 风险、异常与转向路径；
8. 阶段完成和下一阶段交接。

### 2.4 多 Agent 只形成一份行动方案

每件事只有一个主责 Agent，其他 Agent 在后台协作。所有结论最终写入同一份家庭档案、计划、待办和日历，避免多个 Agent 各自输出互相冲突的建议。

### 2.5 医疗过程由专业机构负责

产品负责信息整理、计划管理、风险提示、就医准备、家庭协作和医嘱追踪，不替代医生诊断、用药指导或分娩决策。遇到高风险或不确定情况时，优先引导用户联系医疗机构或及时就医。

## 3. 全程旅程总览

首期孕期用户旅程为：

> 加入 App 并建立计划 → 孕早期 → 孕中期 → 孕晚期 → 临产与分娩住院 → 出院及产后最初几天交接

家庭在全程中始终使用同一份档案、计划和 Agent 团队。阶段变化会改变首页重点、常用工具、任务优先级和活跃 Agent，但不会割裂用户数据或历史。

## 4. 阶段 0：首次进入与建立孕期计划

### 4.1 用户处境

用户可能刚确认怀孕，也可能已经完成部分产检，甚至临近分娩。她通常带着一个当前问题进入产品，而不是准备先完整填写一套资料。

### 4.2 核心目标

快速识别当前孕周、家庭状态和紧迫事项，生成第一版可执行计划，使用户首次使用后立即知道现在应该做什么。

### 4.3 需要了解的关键信息

- 预产期或当前孕周；
- 是否已确认相关基本医学情况；
- 当前身体状况及既往健康情况；
- 是否已有产检报告；
- 建册、建档和意向医院情况；
- 居住地、户籍、医保与工作状态；
- 伴侣及其他家庭支持情况；
- 当前最担心、最想解决的问题。

这些信息可以通过简短交流、手动填写和资料导入逐步获得，不要求一次完成。

### 4.4 产品与 Agent 行动

成长规划 Agent 主责，孕产 Agent、健康就医 Agent和杭州生活事务 Agent 等按需参与。

系统应：

- 识别当前孕周和阶段；
- 找出需要立即处理的风险或时限事项；
- 判断已完成、待确认和可能遗漏的任务；
- 建立今天、未来一周和未来四周的计划；
- 配置当前活跃 Agent 团队；
- 逐步建立必要的记录习惯；
- 说明需要立即关注的风险信号。

### 4.5 阶段结果

用户首次完成引导后，应直接获得：

- 当前阶段说明；
- 今天最重要的事项；
- 接下来四周的关键计划；
- 可能遗漏的产检或本地事务；
- 当前需要建立的记录；
- 当前服务她的 Agent 团队；
- 需要立即关注的风险边界。

## 5. 阶段 1：孕早期——确认、建档与建立安全感

### 5.1 用户处境

孕早期通常伴随身体不适、结果不确定、信息混乱和对风险的担忧。用户既需要处理检查和建档，也需要适应身体和心理变化。

### 5.2 核心目标

完成基本情况确认，进入规范孕期管理，并建立能够持续执行的日常生活与随访节奏。

### 5.3 关键事项

- 确认孕周及相关医学情况；
- 选择就诊医院并完成首次产前检查；
- 建立《母子健康手册》和孕期健康档案；
- 整理既往病史、用药、过敏史和已有报告；
- 了解产前筛查的意义、时间窗口和有资质的机构；
- 管理孕吐、疲劳、饮食、睡眠和情绪；
- 完成杭州本地建册、医院选择和权益准备；
- 识别需要及时联系医院或就医的异常情况。

### 5.4 Agent 协作

孕产 Agent 主责，健康就医 Agent、营养 Agent、妈妈照护 Agent和杭州生活事务 Agent 协作。

Agent 应主动：

- 生成孕早期阶段计划；
- 根据用户当前进度补齐遗漏事项；
- 整理检查前准备和问诊问题；
- 将检查报告写入档案并生成后续任务；
- 建立必要的症状、体重、饮食和情绪记录；
- 根据身体状态调整任务负担；
- 发现风险信号时停止普通建议并明确引导就医。

### 5.5 阶段交接

孕早期完成不只以孕周为判断依据。进入孕中期前，基础档案、首次检查、孕期管理关系和后续计划应已经建立；未完成事项继续带入孕中期追踪。

## 6. 阶段 2：孕中期——稳定管理与系统准备

### 6.1 用户处境

孕中期身体状态通常相对稳定，但检查节点增多，家庭也开始从确认怀孕转向为分娩和宝宝到来做准备。

### 6.2 核心目标

持续掌握妈妈与胎儿情况，在不制造额外焦虑的前提下，把健康管理、家庭准备和生活安排逐步推进。

### 6.3 关键事项

- 根据医生安排完成产检和相关筛查；
- 上传并整理检查报告，追踪复查事项；
- 记录体重、症状、饮食、运动、睡眠和情绪变化；
- 在医生指导下开始关注胎动；
- 根据实际身体情况调整营养和活动计划；
- 初步了解分娩医院、生产方式和孕产服务；
- 启动待产用品、预算、月嫂或家庭照护方案；
- 规划工作安排、产假和家庭分工；
- 识别检查异常和需要增加随访的情况。

### 6.4 Agent 协作

孕产 Agent 主责，健康就医 Agent、营养 Agent、妈妈照护 Agent、家庭协作 Agent和杭州生活事务 Agent 参与。

Agent 应主动：

- 根据产检结果调整后续计划；
- 把医生要求转化为复查、记录和观察任务；
- 识别体重、饮食或身体变化趋势并提出行动；
- 分批生成用品和服务决策，避免一次堆积大量任务；
- 提前推动家人分工、产假和预算安排；
- 在孕晚期前形成第一版待产准备计划。

### 6.5 阶段交接

进入孕晚期前，重要检查应得到跟进，日常管理节奏应相对稳定，分娩医院和照护方向初步明确，家庭已经开始有序准备。

## 7. 阶段 3：孕晚期——监测、待产与随时行动

### 7.1 用户处境

孕晚期的关注点从按计划准备逐步转向什么时候会发生、发生时怎么办。产检更频繁，身体负担增加，家庭需要具备随时行动的能力。

### 7.2 核心目标

持续关注妈妈和胎儿情况，同时完成待产、就医和家庭协作准备，使家庭能够在临产事件发生时有序行动。

### 7.3 关键事项

- 根据医生安排完成产检和复查；
- 持续记录胎动、身体症状、体重、睡眠和情绪；
- 整理临产信号、异常信号和就医路径；
- 确认分娩医院、入院入口、路线、交通及联系人；
- 完成待产包、证件、资料和费用准备；
- 理解可能的分娩方式和医院流程，形成生产偏好；
- 明确伴侣及家人的陪护、交通、物品和沟通分工；
- 安排工作交接和必要家庭事务；
- 准备出院后妈妈恢复和新生儿照护的基础条件。

### 7.4 Agent 协作

孕产 Agent 主责，健康就医 Agent、妈妈照护 Agent、家庭协作 Agent和杭州生活事务 Agent 深度参与。

Agent 应主动：

- 提高关键事项优先级，减少非必要任务；
- 检查待产准备缺口；
- 将就医路径、联系人和资料整理成应急卡片；
- 根据产检结果和医生意见持续调整计划；
- 自动向家庭成员分配任务并追踪完成情况；
- 用户记录宫缩或异常症状时，进入临产或风险处理流程。

### 7.5 阶段交接

孕晚期完成不以预产期到来为唯一标志。家庭应具备随时行动的条件，并能在临产事件发生时直接切换到分娩模式。

## 8. 阶段 4：临产与分娩住院——从计划切换为事件处置

### 8.1 触发方式

当用户记录规律宫缩、破水、见红、胎动异常，或医生安排入院时，App 从日常孕期模式切换为分娩模式。

是否需要立即就医应遵循医疗机构提供的规则和专业意见。产品不自行替代医生判断。

### 8.2 核心目标

减少家庭慌乱，缩短从发现事件到采取正确行动的路径，并保持医疗信息、物品和家庭分工完整。

### 8.3 分娩模式重点

分娩模式暂停或延后无关任务，只保留当前必须处理的事情：

- 识别需要立即联系医院或急救的情况；
- 显示医院入口、路线、电话和就医方式；
- 启用宫缩记录等必要工具；
- 提醒携带证件、病历资料和待产物品；
- 通知已授权的家庭成员；
- 激活交通、陪护、物品和家庭沟通分工；
- 将健康档案整理为便于就医查看的摘要。

### 8.4 Agent 协作

孕产 Agent 主责，健康就医 Agent 负责风险和医疗信息，家庭协作 Agent 负责家属行动，杭州生活事务 Agent 提供医院及本地办事支持。

这一阶段的交互应简短、明确、顺序化，避免展示复杂知识或要求用户完成大量输入。

### 8.5 住院记录

用户或家人可以记录：

- 入院时间和医院；
- 医生告知的重要情况；
- 检查、用药和临时安排；
- 需要家属处理的事项；
- 分娩结果及妈妈、宝宝的基本情况。

### 8.6 阶段交接

分娩完成后，系统根据分娩结果和医院安排自动切换到住院及出院交接阶段，而不是直接跳入完整育儿模式。

## 9. 阶段 5：住院、出院与产后最初几天——完成自然交接

### 9.1 用户处境

宝宝出生后，家庭需要同时处理妈妈恢复、宝宝观察、医院事项、医生交代和回家准备，精力有限且信息密集。

### 9.2 核心目标

帮助家庭从医院安全回到家庭，确保妈妈和宝宝的关键档案、医嘱、复查和最初几天照护不存在无人处理的断点。

### 9.3 住院期间关键事项

- 记录分娩方式、时间及妈妈和宝宝的基本情况；
- 整理医生、护士告知的重要信息；
- 跟踪检查、用药、伤口、喂养和观察事项；
- 管理出生医学证明等院内事项；
- 记录需要复查、随访或继续观察的问题；
- 明确家属每天需要处理的物品、陪护和沟通任务。

### 9.4 出院回家计划

Agent 应主动生成：

- 妈妈需要继续观察和护理的事项；
- 宝宝喂养、睡眠、排便和身体状态的基础记录；
- 妈妈和宝宝需要复查、访视或就医的时间；
- 医嘱、药物和材料的整理；
- 杭州出生后办事的后续任务；
- 家庭成员在最初几天的照护分工；
- 必须及时联系医院或就医的风险信号。

### 9.5 首期产品边界

产品在此阶段提供安全交接所需的基础支持，但不全面展开育儿期的喂养、睡眠、成长和早教 Agent。

首期孕期用户旅程完成的标志是：

> 家庭已顺利出院，妈妈与宝宝的关键档案已建立，医嘱和复查已转化为计划，最初几天的照护分工已明确，后续事项不存在无人处理的断点。

## 10. 异常与非标准旅程

用户旅程不能假设所有孕期都按标准阶段平稳推进。出现检查异常、高危妊娠、住院观察、提前分娩或其他重大变化时，系统应：

1. 暂停不再适用的常规计划；
2. 由健康就医 Agent 和孕产 Agent 重新判断当前主线；
3. 优先写入医生要求和医疗机构安排；
4. 重新生成当前阶段计划和家庭分工；
5. 明确 Agent 能处理与不能处理的部分；
6. 保留原有记录和变更原因，确保全过程可追溯。

异常旅程不另建一套割裂产品，而是在同一家庭时间线中根据真实事件动态调整。

## 11. 用户旅程验收标准

完整孕期旅程的验收不以是否展示全部知识或是否建立大量页面为标准，而以以下结果判断：

- 用户可在任何孕周加入并迅速获得可用计划；
- 每个阶段都明确告诉用户当前重点和下一步行动；
- 检查报告、医生要求和用户记录能持续改变后续计划；
- 多 Agent 协作后只输出一份统一方案；
- 任务能被创建、分配、追踪、调整和完成；
- 临产时产品能从日常模式迅速切换为事件处置；
- 分娩后能够完成住院、出院与最初几天的自然交接；
- 高风险和不确定事项清楚升级给医疗专业人员；
- 家庭始终知道 Agent 做了什么、为什么做和哪些事项需要自己决定。

## 12. 下一阶段

用户旅程确认后，下一阶段应基于这条主线梳理首期功能结构：逐一确定每个阶段需要哪些功能、功能承担什么用户任务、Agent 可以调用哪些 Tool，以及不同功能之间如何共同完成关键场景闭环。

整体系统边界和 Agent 运行方式已在《孕期 AI Agent App 整体架构方案》中定义。首期功能结构应以本用户旅程为业务主线，并遵循该整体架构。
