# 补缺口 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 待办在第 4–42 周每周都有可做的事并随孕周自动续上；危险信号扩到约 16 条、三档自查，AIM 也能读到。

**Architecture:** 内容在 `content/pregnancy-tasks/` 与 `content/safety-rules/`。续任务用新表 `plan_template_seeds` 记住「生成过哪些模板」，由 `GET /today`、`GET /plan` 与 Agent `list-tasks` 在读取前幂等调用 `sync_week_tasks`。危险信号加 `weeks` 与三档 `urgent/same_day/routine`，接口支持 `?week=`，Agent 的孕期上下文附带当前孕周的危险信号。

**Tech Stack:** FastAPI + SQLAlchemy（async，Postgres）+ Alembic + pytest；Eve agent（TypeScript）；SwiftUI + XCTest。

规格：`docs/superpowers/specs/2026-10-10-fill-gaps-design.md`。

## Global Constraints

- 所有面向用户的文字、注释、提交信息用简体中文。
- 现有模板文件 `week-05-12.yaml`、`week-18.yaml` 与其条目 `id` 不得修改（已在用户计划中作为 `source_id`）。
- 模板 `id` 全局唯一；第 4–42 周每周至少一个模板文件覆盖。任务标题 ≤20 字、摘要 ≤60 字；检查时间写「按医生安排」或指南常见孕周；杭州政策类只写去哪里查、准备什么。
- 续任务只生成「覆盖当前孕周、且该计划从未生成过」的模板；删除过的不复活；跳过的孕周不补；无计划时不做事；sync 失败不影响读取（记日志、照常返回）；并发靠 `(plan_id, template_id)` 主键兜底。
- 系统续上的任务：`source_type = template`、`changed_by_actor_type = system`、`due_at = as_of + due_in_days` 的 09:00 UTC；不写家庭动态。
- 危险信号 `severity ∈ {urgent, same_day, routine}`；可选 `weeks: [起, 止]`（4–42）；`GET /api/v1/safety-rules` 不传 `week` 时返回全部（旧版 App 兼容）。
- iOS 自查三档：任一 urgent → 「请立即联系产检医院或拨打 120」；否则任一 same_day → 「今天或明天联系你的产检医院」；否则 → 「记下来，下次产检时告诉医生」。
- 内容由 Claude 起草并对照《孕前和孕期保健指南（2018）》等自审，审核记录写进 `content/README.md`。
- 测试：API 在 `services/api` 下 `PYTHONPATH=src python3 -m pytest`（Postgres 127.0.0.1:55434）；本机无 ruff，用 `uvx ruff check <文件>`；iOS 用 iPhone 18 Pro；不要停或重建除 api 外的容器。

    async def seeded_template_ids(self, plan_id: UUID) -> set[str]:
        rows = await self.session.scalars(
            select(PlanTemplateSeedModel.template_id).where(PlanTemplateSeedModel.plan_id == plan_id)

    async def try_seed(self, plan_id: UUID, template_id: str, now: datetime) -> bool:
        # 并发的两次 sync 只有一方能插入成功，另一方据此跳过建任务。

            .returning(PlanTemplateSeedModel.template_id)
        )

`sync_week_tasks.py`：

```python
"""孕周推进时续上本周任务。

只生成覆盖当前孕周、且这个计划从未生成过的模板——种子表记着「生成过」，
用户删掉的任务因此不会复活；跳过的孕周不补，过时的提醒不如不提醒。
"""

from __future__ import annotations

from dataclasses import dataclass
from datetime import UTC, date, datetime, time, timedelta
from uuid import UUID, uuid4

from aim_api.contexts.guidance.application.queries.get_guidance import initial_plan_items
from aim_api.contexts.planning.application.ports import PlanningUnitOfWork
from aim_api.contexts.planning.domain.task import ActorType, Task, TaskSourceType


@dataclass(frozen=True, slots=True)
class SyncWeekTasksCommand:
    pregnancy_id: UUID
    as_of: date


async def execute(command: SyncWeekTasksCommand, uow: PlanningUnitOfWork) -> int:
    pregnancy = await uow.pregnancy_ownership.get_pregnancy(command.pregnancy_id)
    if pregnancy is None:
        return 0
    plan = await uow.repository.get_plan(command.pregnancy_id)
    if plan is None:
        return 0
    week = pregnancy.gestational_age(command.as_of).weeks
    seeded = await uow.repository.seeded_template_ids(plan.id)
    now = datetime.combine(command.as_of, time(0), tzinfo=UTC)
    created = 0
    for item in initial_plan_items(week):
        if item.id in seeded or not await uow.repository.try_seed(plan.id, item.id, now):
            continue
        task = Task.create(
            task_id=uuid4(),
            plan_id=plan.id,
            pregnancy_id=command.pregnancy_id,
            title=item.title,
            description=item.summary,
            source_type=TaskSourceType.template,
            source_id=item.id,
            changed_by_actor_type=ActorType.system,
            changed_by_actor_id=None,
            due_at=datetime.combine(command.as_of + timedelta(days=item.due_in_days), time(9, 0), tzinfo=UTC),
            assigned_member_id=None,
            now=now,
        )
        await uow.repository.add_task(task)
        created += 1
    if created:
        await uow.commit()
    return created
```

（`Task.create` 参数名以 `generate_initial_plan.py` 的调用为准；`get_pregnancy` 返回对象有 `gestational_age`——以 `POST /plan` 的写法为准。`try_seed` 已插入但随后 `add_task` 前出错的情况由同一事务回滚覆盖。）
