# 分娩记录关联修复验收

日期：2026-10-12。起点 `9c4c63e`，分支 `dev/labor-links-emotional-care`。

## 修复

- 计时页与分娩页统一使用 `HospitalTripLink`：超过六小时的旧计时先明确选择处理方式，不自动关联当前出发；未来时间的历史记录不关联。
- 保存旧计时、丢弃旧计时、先出发稍后处理均可继续进入出发确认页。保存最多等五秒，失败或超时保留待补存队列；旧计时作为历史归档，不附加到本次出发。
- 前台补存与出发保存共用同一 Task，循环记录「本地结果 id → 服务端记录 id」，并发调用不再直接返回 nil，不重复新建，也不把补存旧记录误当作当前计时。
- 绑定改变使用新的 generation 与保存任务；旧回执清理旧队列，不更新新作用域状态，不返回旧关联编号。
- 取消超时任务后检查取消状态，避免快速保存误报超时。假仓库使用 MainActor 隔离，不再带无保护的 Sendable 可变状态。
- 保存期间禁用计时编辑。Debug 配置显式定义 DEBUG；仅 Debug 支持测试时钟偏移，Release 不包含该测试入口。

## 验证

- 旧实现缺少旧计时决策，新增回归先失败；修复后宫缩模型与保存测试 43 个通过。
- 全部 iOS 单元测试 **515 个通过**，含并发补存、新作用域不阻塞、旧回执无关联、六小时边界、未来历史、旧计时三种处理选择。
- 原分娩 UI 主旅程通过：计时→保存→出发→首页横幅→撤回。
- 新增 UI 通过：使用测试时钟创建旧计时→重启恢复→分娩页选择稍后处理→出发确认可打开→计时页仍保留旧断点→计时页选择丢弃并继续→旧断点清理。
- 新 UI 首次运行未定义 DEBUG，测试时钟未启用，创建成了当下计时而未出现旧计时选择；修正构建配置后独立回归通过。首次失败后的 xcodebuild 收尾挂起，终止本次测试进程后重跑，没有重启其他服务。
