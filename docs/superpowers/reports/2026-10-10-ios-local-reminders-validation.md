# iOS 本地提醒验收记录

日期：2026-10-10。分支 `dev/ios-local-reminders`，起点 `0b71ed3`。

## 交付

- 家庭 → 个人资料 → 提醒设置：总开关默认关闭，用户保存开启时申请系统通知权限；权限拒绝后给出系统设置入口。
- 每日胎动、产检/待办到期、本周简报三个开关。胎动时间可设，默认 20:00；每周一 09:00 提示查看简报；默认免打扰 22:00–08:00，均按北京时间。
- 胎动仅在孕 28–42 周安排；当天已记录或正在计数时不再提醒。待办只提醒未完成、分配给自己或未分配的事项。
- 时间取 `dueAt ?? scheduledFor`，与待办列表一致；后端 delay 只改 dueAt，不能用旧 scheduledFor 排提醒。通常提前 1 小时，不足 1 小时的未来事项到期时提醒；已过期不补发。
- 免打扰中的待办提醒提前到该段开始前；胎动和简报移到结束时刻，不把待办推迟到截止时间以后。
- 未来 28 天、最多 60 个一次性请求，最近时间优先；App 打开、数据和偏好变化时重排。完成、改期、分工、新建与删除待办后都会触发更新。
- 通知正文不展示具体待办、病史、用药或报告；userInfo 仅携带 scope 与路由编号。点击后核对当前 scope：待办取最新详情，胎动进入既有计数页，本周简报读取实时计划和记录。
- 启动时注册 delegate，冷启动响应保留到仓储就绪再消费。登录态/家庭/孕期变化立即撤销旧请求；异步添加期间切换 scope 也会撤掉刚完成的旧请求。
- 提醒开关关闭、退出、注销或会话过期均撤销旧计划；偏好按账号保存在本机，不串到另一个账号。
- 本周简报展示当前排在本周的安排、当前状态与本周记录，不推断任务完成时间，不在后台生成 AI 医疗内容。

## 验证结果

- iPhone 18 Pro / iOS 27 本地签名构建：**455 个单元测试通过**，其中新增 21 个提醒用例。
- 用例覆盖孕周边界、已有记录与计数抑制、短期事项、过期/完成/分工过滤、改期与稳定编号、跨日/同日免打扰、容量、请求内容与一次性日历触发、拒绝授权、授权时前台刷新竞态、换家庭、换账号、登出中的异步添加、读取失败撤销、冷启动待处理路由与 Keychain 往返。
- 真实系统 UI：注册 → 开启并保存 → 系统授权 → 重启后偏好与登录态恢复 → 发 10 秒测试提醒 → 终止 App → 系统实际显示通知 → 点击冷启动 → 进入本周简报并读到最新数据，通过。
- 同一真实 UI 流程继续验证关闭开关后安排为 0、测试按钮不可用；重新开启并排入第二条测试通知后退出登录，在原定送达窗口未收到旧账号通知，通过。
- 记忆手动新增、编辑、私有、新会话读取、删除 UI 回归通过。
- 产检报告、异常标记、异常项加入想问医生 UI 回归通过。签名包的系统保存密码弹窗可能晚于注册请求出现，测试补了延后处理与日期选择点击重试，没有改业务准入逻辑。
- `make verify`：API **454 passed**；Agent **56 passed / 3 skipped**；lint、契约与目录检查通过。
- 系统通知截图、提醒设置和简报截图已检查。

## 构建与验证边界

- 模拟器关闭代码签名时，登录信息的普通偏好项仍存在，但 Keychain 登录态未能在重启后恢复；本地 ad-hoc 签名的构建完成了真实冷启动验证。`make ios-build` / `make ios-test` 已采用模拟器本地签名，不涉及发行证书或生产发版。
- 系统送达与冷启动验收使用“测试提醒 → 本周简报”；其他类别的日期、路由与作用域规则由单元测试验证，并复用已存在的原生页面。
- 本地通知按本机最近同步的事实排队；其他设备的改动等本机下次同步后生效。长期不打开 App 不自动续排；iOS 的通知权限、专注模式与系统策略仍会影响展示。没有新增 APNs 或后台实时同步保证。
