# AIM 支持图片 设计规格

2026-09-30

## 1. 目标

让用户在 AIM 对话里发图片，由 AI 处理。三种用途：

- **识别产检报告并录入**：拍报告单，AIM 读出体重、血压、空腹血糖、血红蛋白和医生建议，新建产检记录，原图挂在记录上。
- **拍照提问**：拍食物、药盒、身体状况问问题，只回答，不建记录。
- **存档原图**：「把这张 B 超单存起来」，建一条备忘记录并挂上原图，以后在记录详情里看原件。

不做：PDF 等文件、手动录入页面加图（只从 AIM 进）、模型主动提问。

## 2. 已确认的决策

- **模型改用 `deepseek-flash`**。已实测：能读图（测试报告单 5 项全部读对），带图时能正确调用「新建产检记录」工具并填对数值。线上的 `deepseek-chat` 已被 DeepSeek 指向同一个模型，改名只是把配置写明确。
- **按 Eve 官方推荐的方式传图**：图片内容直接放进消息。Eve 另一种「只传地址、需要时再取」的方式只有自定义接收入口才支持，默认入口不支持，不值得为此自写入口。代价是图片内容会进对话记录，靠压缩和数量上限控制。
- **原图存在服务器本地磁盘**（独立数据卷）。存储读写封装成一层，以后换阿里云对象存储只换这一层。
- **只从 AIM 进，原生页面只负责展示**。
- **报告单识别后直接建记录，不单独确认**，与「新建记录直接做、事后可撤销」的既有规则一致。卡片列出识别到的每一项，读错了撤销或让 AIM 改。
- **不开放模型提问**（沿用上一轮决定）。

## 3. 整体流程

1. 用户在 AIM 输入框点图片按钮，拍照或从相册选，最多 4 张；输入框上方显示缩略图，可删。
2. 选图时网页把每张图缩到最长边 1600 像素、JPEG 质量 0.8；点发送时逐张上传到业务服务，拿到附件编号。任何一张上传失败，输入框上方提示「图片上传失败」，消息不发出，图片留在输入框里，再点发送即重试。
3. 全部上传成功后，把文字和图片一起发给 Eve；同时用「每轮附带的上下文」告诉模型本段对话里所有图片的编号（按发送顺序，带「第几条消息的第几张」）。
4. 模型看图处理；需要挂图时，把编号填进「新建记录」的附件参数。
5. 业务服务校验附件归属后挂到记录上。
6. 对话里用户消息显示缩略图（Eve 的对话记录里本来就有图片内容）；记录详情页（原生）显示挂着的图片。

**编号只在本次打开的对话页面里记着**：重新打开旧对话后网页不记得之前的编号，这时说「把刚才那张存起来」，AIM 会请用户重发。多数情况下发图和存图在同一次使用里，可以接受。

## 4. 业务服务

### 4.1 数据

新表 `attachments`（迁移 `0010_attachments`）：

| 列 | 说明 |
| --- | --- |
| `id` | UUID，附件编号 |
| `family_id` | 所属家庭（与记录表一致不设外键，注销清理时显式删除） |
| `pregnancy_id` | 所属孕期 |
| `uploaded_by` | 上传账号 |
| `media_type` | 只允许 `image/jpeg`、`image/png`、`image/webp`（网页统一压成 JPEG 再传，其余两种留给以后的入口） |
| `byte_size` | 字节数，不超过 2 MB |
| `record_id` | 挂在哪条记录上，可空 |
| `created_at` | 上传时间 |

记录上已有的 `attachment_refs`（附件编号列表）放开使用：领域层去掉「附件保留未用」的限制，改为只接受本家庭、未挂到其它记录的附件编号。

### 4.2 存储

- 文件存放在数据卷 `aim_attachments`，挂到业务服务容器的 `/data/attachments`，路径按编号：`/data/attachments/<编号前两位>/<编号>`。
- 读写经一个存储接口（保存、读取、删除，以及供清理用的列出全部文件），本期只有本地磁盘实现。写入先写临时文件再改名，避免留下半张图。

### 4.3 接口

| 接口 | 行为 |
| --- | --- |
| `POST /api/v1/pregnancies/{id}/attachments` | 需登录且是该孕期家庭的成员；请求体为图片原始字节，类型取自请求头；超过 2 MB 返回 413，类型不对返回 415。返回 `{id, media_type, byte_size}`。 |
| `GET /api/v1/attachments/{id}` | 需登录且是附件所属家庭的成员，否则 404（不暴露是否存在）。返回图片字节，带正确的类型头和长期缓存头。 |
| 内部工具「新建记录」 | 增加 `attachment_ids`，最多 4 个；逐个校验同家庭、未挂靠，然后写入记录的 `attachment_refs` 并在附件表上标注 `record_id`。校验失败返回可读的中文错误给模型。 |
| 记录列表与详情 | 已有的 `attachment_refs` 字段开始有值。 |
| 删除记录 | 记录本身是软删除、可以撤销恢复，所以附件先保持挂靠、不删文件；由清理任务在记录删除 30 天后删图。 |

撤销「新建记录」（按操作编号撤销）同样是软删记录，附件处理同上。

### 4.4 清理与备份

- 新脚本 `purge_orphan_attachments.py`，删除三类：一是没挂到任何记录、上传超过 90 天的；二是所挂记录已删除超过 30 天的（这两类删行和文件）；三是数据库里已没有对应行、且文件修改时间超过 1 小时的孤儿文件（避开正在上传的图）。服务器 crontab 每天跑一次，写进部署文档。
- 注销清理（`PurgeExpiredDeletions`）：清家庭数据时显式删除该家庭的附件行；本人私密记录上的附件行随私密记录一起删；其余附件的上传人置空。文件不在注销用例里删，由上面的每日清理按「孤儿文件」扫掉。
- 每日备份脚本加一步：打包 `aim_attachments` 数据卷，保留 7 天，与数据库备份一致。

## 5. AIM（Eve）

- 模型：部署环境变量 `AIM_AGENT_MODEL=deepseek-flash`，代码默认值同步改为 `deepseek-flash`。
- 打包：运行镜像带上构建阶段生成的沙箱模板目录。缺了它，Eve 暂存附件时整段会话直接报错（本地已复现并验证修法）。
- 接收入口：上传限制设为只收图片、单个不超过 2 MB。
- 工具「新建记录」：增加 `attachmentIds`（最多 4 个，UUID）。
- 系统指令新增一段「图片」：
  - 本段对话里用户发过的图片编号在每轮上下文里，按「第几条消息的第几张」给出；
  - 报告单：读出能看清的指标，建产检记录并挂原图；**看不清或不确定的数值不要猜，直接说哪一项没看清**；
  - 拍照提问：只回答，不建记录，不挂图；
  - 用户说「存起来」：建备忘记录并挂图；
  - 编号不在上下文里（例如旧对话）：请用户重新发图，不要编造编号。

## 6. 网页（对话界面）

- 输入框左侧加图片按钮，用系统的文件选择（只收图片，可多选），iOS 上会弹出拍照、照片图库等选项。
- 选图后在前端压缩（最长边 1600 像素，JPEG 0.8），超过 4 张时只保留前 4 张并提示。
- 输入框上方显示缩略图条，每张可删；上传失败或超过张数时在输入框上方显示提示，图片留在输入框里，再点发送即重试。
- 发送顺序：全部上传成功 → 发消息（文字 + 图片内容）→ 更新本页记住的图片编号列表 → 每轮通过附带上下文把编号给模型（与「正在看：…」的页面上下文合并在同一份上下文里）。
- 用户气泡里渲染图片缩略图，点开看大图。
- 「新建记录」卡片在有附件时显示「已附上 N 张图」。

## 7. App（原生）

- 声明相机权限说明：「用于拍摄产检报告等，交给 AIM 识别」。从相册选图走系统选择器，不需要相册权限。
- 记录模型读取 `attachment_refs`；记录详情页显示缩略图网格，点开全屏查看、可双指缩放。
- 图片加载带登录信息；加载失败显示占位图。

## 8. 验证

- 业务服务：上传（大小、类型、非成员）、查看（跨家庭 404）、挂到记录（同家庭、未挂靠、数量上限）、删记录后附件保留、两类清理（未挂靠 90 天、记录删除 30 天）、注销清理，全部写集成测试。
- AIM：工具参数映射与上限的单元测试；指令改动后用测试报告图在本地实跑「发报告 → 产检记录 → 挂原图」。
- 网页：压缩尺寸计算、每轮上下文里编号列表的构造写单元测试；浏览器里走完选图、压缩、上传、发送、气泡显示。
- App：记录详情显示与全屏查看的单元测试；模拟器打开带图记录；真机实拍一次。
- 部署：确认线上新数据卷已挂载、备份包含图片、清理任务已加入 crontab。

## 9. 风险

- **对话记录变大**：每张图压缩后仍有几百 KB，图多的对话打开会慢。靠压缩和每条 4 张的上限控制；真成问题时改用自定义接收入口按需取图。
- **识别错误**：健康数据读错有风险。靠「不确定不要猜」的指令、卡片逐项列出数值、可撤销来兜底；指标本身也有合理范围校验（已有）。
- **磁盘容量**：服务器剩 24 GB，按每张 0.5 MB 估算可存数万张；清理任务保证未挂靠的图不会无限增长。
