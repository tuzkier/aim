# AIM 会话列表

让 AIM 的对话可以翻回去看，而不是每次打开都从零开始。

## 为什么现在做

`AgentStore.sessionID` 和 `messages` 都只存在内存里，`AgentStore` 是 `MainTabView` 的
`@State`。App 一重启，会话 id 丢失，历史对话再也找不回来——它其实还在 Eve 里，只是
没有任何入口。

## 关键实测

Eve **没有**列会话的接口（`GET /eve/v1/sessions` 返回 404），所以列表必须由我们自己维护。

但会话内容可以完整重放：对同一个会话请求 `/eve/v1/session/{id}/stream?startIndex=0`，
拿回 **391 条事件，与首次接收完全一致**，用户消息和 AIM 回复都在。

所以本设计**不复制消息**，只存会话的元信息。一份数据两处存迟早不一致；而且对话内容
涉及隐私，少存一份就少一处泄漏面。

## 决定

| 项 | 选择 | 理由 |
|---|---|---|
| 存储位置 | 服务器 | 换手机、重装 App 都还在 |
| 可见范围 | 只有自己 | 孕期会问很私人的事，默认全家可见会让人不敢问 |
| 打开 AIM | 接着最近那段 | 孕期的问题往往是连着的（「刚才说的那个…」） |
| 快捷入口 | 开新对话 | 一段对话里混十几件不相干的事，以后没法翻 |
| 标题 | 第一句用户消息，截 40 字 | 见「标题」一节 |

## 数据

新表 `agent_sessions`：

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | uuid | 主键 |
| `account_id` | uuid | **按账号隔离**，不是家庭 |
| `family_id` | uuid | 便于按家庭清理，不参与鉴权 |
| `eve_session_id` | text | Eve 的 `wrun_*` |
| `title` | varchar(80) | |
| `created_at` | timestamptz | |
| `last_active_at` | timestamptz | 列表排序依据 |

`account_id` 上建索引——列表查询只按它过滤。

## 接口

| 接口 | 行为 |
|---|---|
| `GET /api/v1/agent/sessions` | 列出自己的会话，按 `last_active_at` 倒序 |
| `POST /api/v1/agent/sessions` | 登记新会话 `{eve_session_id, title}` |
| `PATCH /api/v1/agent/sessions/{id}` | 更新 `title` / `last_active_at` |
| `DELETE /api/v1/agent/sessions/{id}` | 从列表移除 |

所有接口按 token 里的 `account_id` 过滤。**拿别人的会话 id 请求要返回 404 而不是 403**
——403 等于确认了「这个 id 存在」，成了会话 id 的探测通道。

## 标题

取第一句用户消息，去掉上下文前缀（`requestMessage(for:)` 会拼「当前页面：…」），
截到 40 字。

不额外调模型生成摘要：多一次调用、多一处延迟和失败点，而第一句话通常已经说明了
这段对话在讲什么。不够好以后再改。

## iOS

- AIM 页顶部：「历史会话」入口 + 「新对话」按钮
- 会话列表：标题 + 最后活跃时间，左滑删除
- 进入 App 时若本地无会话，拉取最近一条并重放其内容
- 快捷入口（记录、事项的「问问 AIM」）总是新建会话，标题取那条记录

## 已知限制

会话内容存在 Eve 的 `aim_eve-workflow-data` 卷里，**该卷不在数据库备份范围内**。
卷被清掉后（本项目 2026-08-24 清过一次），列表还在但内容为空。

列表在重放不到内容时显示「这段对话的内容已不可用」，而不是转圈或白屏。

彻底解决需要定期备份该卷，或真的复制一份消息。两者都可以以后再做，当前不值得。
