# 个人资料与家庭交互 设计规格

2026-10-02

## 1. 目标

- 新增个人资料页：看和改自己的称呼、身份；看和改全家共享的预产期（可按预产期、末次月经或当前孕周填写）；账号设置（法律页、退出登录、注销）挪到这里。
- 把邀请家人真正走通：被邀请的人用该手机号注册或登录后，在 App 里看到邀请并接受。
- 家庭页做更丰富的交互：重新编排、成员详情、家庭动态、退出家庭、移出成员。

一次做完，不分期。

不做：修改密码、孕期健康档案（身高、血型等）、邀请码、短信通知、AIM 改预产期的工具、合并两个家庭的数据。

## 2. 已确认的决策

| 问题 | 决定 |
| --- | --- |
| 个人资料范围 | 预产期 / 孕周、称呼和身份 |
| 谁能改预产期 | 家里任何在籍成员；改动进家庭动态 |
| 改预产期后已有待办 | 不动（初始待办的日期按建档日往后推算，与孕周无关） |
| 被邀请人怎么加入 | 按手机号：用该号注册或登录后 App 弹出邀请 |
| 被邀请人已有家庭 | 原家庭「没有内容」才能接受，接受后原家庭删除；有内容则不能接受 |
| 家庭页新增 | 成员详情、家庭动态、成员管理 |
| 谁能移出别人 | 只有管理员（家庭创建人 `families.created_by`）；其他人只能自己退出 |
| 页面结构 | 家庭页顶部「我」卡片进入个人资料；标签栏保持 4 个 |

## 3. 页面

### 3.1 家庭页（重新编排）

自上而下：

1. **「我」卡片**：头像（称呼首字）、「称呼 · 身份」、副标题「个人资料与账号设置」，点击进入个人资料。
2. **家庭卡片**：家庭名（右侧「改名」）、「孕 31 周 +1 天 · 距预产期 62 天」、孕期进度条（0–40 周）、成员头像条，末尾一个「+」进入邀请。没有孕期时显示「还没有孕期信息」和「去填写」。
3. **家庭成员**：每行「称呼 + 身份 · 管理员标记」，右侧「N 项待办 ›」，点击进成员详情。下面列出待处理的邀请：「138****5678 · 外婆 · 等待加入」或「已过期」，点击弹邀请详情。末行「邀请家人」。
4. **家庭动态**：最近 20 条，滑到底自动加载更早的。

原「改我的称呼和身份」入口和「账号」分组从家庭页移除。

### 3.2 个人资料页（家庭 → 我）

- 头部：大头像、称呼、「身份 · 手机号（138****1234）」。
- **我在家里**：称呼、身份，点击打开现有的编辑面板（`EditMyMembershipSheet`，挪到新文件）。
- **孕期（全家共享）**：预产期、当前孕周；点击打开改预产期面板。没有孕期时显示「填写预产期」，走建档的新建孕期流程。
- **待处理邀请**：有「暂不」过的邀请时出现，每条可「加入」。
- **账号**：隐私政策、用户协议、退出登录、注销账号（原 `AccountSection` 与弹层整体搬过来，行为不变）。

### 3.3 改预产期面板

- 分段选择：预产期 / 末次月经 / 当前孕周。
- 预产期、末次月经用日期选择；当前孕周用「周（0–42）+ 天（0–6）」两个滚轮。
- 实时显示换算结果：「对应预产期 2026 年 12 月 1 日，现在孕 31 周 +1 天」。
- 一律按 280 天换算成预产期提交；换算后今天的孕周不在 0 周 0 天到 42 周 0 天之间时不能保存，并说明原因（「这个日期算出来已经超过 42 周了」等）。
- 与当前预产期相同时「保存」不可用。
- 换算逻辑复用建档页的 `PregnancySetupModel`，扩展出「当前孕周」模式。

### 3.4 成员详情

- 头部：头像、称呼、身份、管理员标记、「2026 年 9 月 1 日加入」。
- **TA 负责的待办**：未完成、指派给 TA 的待办，可勾选完成，点击进待办详情。没有时写「没有指派给 TA 的待办」。
- **TA 最近记的**：TA 写的、当前用户看得到的最近 5 条记录（全家可见，或当前用户自己的私密记录），点击进记录详情。
- 底部按钮：
  - 本人：「改称呼和身份」（打开编辑面板）、「退出家庭」（家里只剩自己时不显示）。
  - 管理员看别人：「移出家庭」。

### 3.5 邀请

- **发邀请**（沿用现有面板）：手机号 + 身份。发出后成员列表出现待处理一行，面板提示「让 TA 用这个手机号注册或登录 AIM」。
- **邀请详情**（点待处理那一行）：手机号（打码）、身份、谁邀请的、几号过期；管理员或邀请人可「撤回」；已过期的可「重发」（新建一条，旧的作废）。
- **被邀请人**：查询「发给我的邀请」的时机有两个：「填写预产期」页（新注册的人一定先到这里）顶部直接列出邀请；进入主界面后也会查一次。有待处理邀请时逐条弹出：「老王邀请你以外婆的身份加入『我们的家』」，按钮「加入」「暂不」。
  - 原家庭没有内容：「加入」后确认框说明「你现在的家庭和其中自动生成的孕期、待办会被删除」，确认后加入。
  - 原家庭有内容：不显示「加入」，改为说明「你的家庭里已经有记录或待办，不能直接加入。可以请对方换一个没用过的手机号邀请你。」和「知道了」。
  - 「暂不」后不再自动弹出，邀请留在个人资料页的「待处理邀请」里直到过期。
- **注册与登录不变**：新注册的人仍会得到一个空家庭（App 注册不带预产期，所以没有孕期），随后进入「填写预产期」页，邀请就显示在这一页顶部。这个空家庭一定「没有内容」，接受邀请时按 §5 清理。这样每个账号始终恰好属于一个家庭，不引入「没有家庭」的状态。

### 3.6 退出与移出

- **退出家庭**确认框：「退出后：你负责的待办会变成未指派；你的私密记录会被删除；你需要新建孕期，或接受别人的邀请。」
- **移出成员**确认框：「移出后 TA 负责的待办会变成未指派，TA 的私密记录会被删除。」
- 家里只剩一个人时不能退出（停用请用注销）。
- 管理员退出时，管理员转给最早加入的在籍成员。
- 退出或被移出的人：服务端立即给其新建一个空家庭（「我的家庭」，没有孕期）。被移出的人的 App 在下次请求原家庭得到 403 时调用 `GET /api/v1/me` 取当前家庭，更新会话，提示「你已不在『我们的家』里」，进入「填写预产期」页（同时展示待处理邀请）。
- AIM 对话历史只列出当前家庭里的对话。

## 4. 数据

迁移 `0011_family_events_and_invitations`：

**新表 `family_events`**（家庭动态里「人」和「孕期」相关的事）

| 列 | 说明 |
| --- | --- |
| `id` | UUID |
| `family_id` | 所属家庭 |
| `kind` | `member_joined` / `member_left` / `member_removed` / `due_date_changed` |
| `actor_account_id` | 谁做的（可空：账号已注销） |
| `subject_account_id` | 涉及谁（加入、退出、被移出的人；可空） |
| `payload` | JSON：`due_date_changed` 存 `{from, to}`；成员事件存 `{display_name}`，人走后动态里仍能显示称呼 |
| `created_at` | 时间 |

索引 `(family_id, created_at desc)`。与现有表一致不设外键；注销清理在删除家庭时显式删这张表的行。

**`family_invitations` 变更**

- 有效期从 24 小时改为 7 天（`Invitation.create`）。
- 状态新增 `declined`（暂不）、`revoked`（撤回）。「暂不」只是不再自动弹出：`declined` 的邀请在过期前仍可接受。
- 发邀请时不再给已有账号的被邀请人插入 `pending` 成员行；已有的 `pending` 成员行在迁移中删除（对应的邀请仍在）。
- 同一家庭、同一手机号只能有一条 `pending` 或 `declined` 的邀请；再邀请时旧的置为 `revoked`。

## 5. 接口

均需登录且账号未停用；家庭类接口要求是该家庭在籍成员。

| 接口 | 行为 |
| --- | --- |
| `PATCH /api/v1/pregnancies/{id}` `{due_date}` | 改预产期。范围按服务端今天的日期检查：0 周 0 天–42 周 0 天，超出 422。写 `due_date_changed` 事件。返回孕期 |
| `GET /api/v1/families/{id}` | 原有；成员项增加 `is_admin`；新增 `invitations`：待处理与已过期（7 天内过期的）邀请，含打码手机号、身份、邀请人、过期时间、状态 |
| `GET /api/v1/families/{id}/members/{account_id}` | 成员详情：成员信息、TA 负责的未完成待办、TA 最近 5 条可见记录 |
| `GET /api/v1/families/{id}/activity?before=&limit=20` | 家庭动态，按时间倒序，`before` 为上一页最后一条的时间。来源见 §6 |
| `DELETE /api/v1/families/{id}/invitations/{invitation_id}` | 撤回；仅管理员或邀请人 |
| `POST /api/v1/families/{id}/invitations` | 原有；行为按 §4 调整，过期重发即再调一次 |
| `GET /api/v1/me/invitations` | 发给我的邀请（按登录账号的手机号），状态 `pending`/`declined` 且未过期；含家庭名、邀请人称呼、身份、`can_accept`（原家庭是否没有内容）和不能接受的原因 |
| `POST /api/v1/me/invitations/{id}/accept` | 接受。邀请失效 409（说明原因）；原家庭有内容 409；否则在一个事务里删除原家庭及其数据、加入新家庭、写 `member_joined` 事件。返回新的 `family_id`、`pregnancy_id` |
| `POST /api/v1/me/invitations/{id}/decline` | 置为 `declined` |
| `POST /api/v1/families/{id}/members/me/leave` | 退出。只剩自己 409。待办取消指派、删私密记录、管理员转移、写 `member_left`、新建空家庭。返回新 `family_id` |
| `DELETE /api/v1/families/{id}/members/{account_id}` | 移出；仅管理员，不能移出自己。后果同退出，写 `member_removed` |
| `GET /api/v1/me` | 当前账号所在的家庭和孕期：`account_id`、`family_id`、`pregnancy_id`、`role`。被移出后 App 用它找回自己的新家庭 |
| `GET /api/v1/agent/sessions` | 只返回当前家庭的对话 |

**「原家庭没有内容」**：该家庭在籍成员只有本人；没有任何记录（含已删除的）；没有孕期信息；没有附件；待办全部来自初始计划（`source_type = template`），且都没有除创建之外的改动记录。

## 6. 家庭动态

接口把以下来源按时间合并，取 `limit` 条：

- `task_changes`：新建（`created`，区分本人与 AIM：`changed_by_actor_type = agent` 时显示「通过 AIM」）、完成。不收改期、指派等细碎改动。
- `records`：全家可见记录的新建（`created_at`）。私密记录不出现。
- `family_events`：成员加入、退出、被移出，预产期修改。

每条返回：`kind`、`actor` 称呼（已不在家的人用事件里存的称呼，注销的显示「已注销的成员」）、标题（待办标题、记录标题或类型名、新旧预产期）、目标（`task_id` / `record_id`，已删除的标 `deleted: true`）、时间。

## 7. AIM

- 系统指令加一句：用户说预产期不对时，告诉用户在「家庭 → 我 → 预产期」修改。
- `get_pregnancy_context` 已从孕期读预产期，改后自然生效，无需改动。

## 8. App 结构

- `Features/Family/FamilyView.swift`：重排，拆出 `FamilyHeaderCard`、成员区、动态区。
- 新文件（在 `project.pbxproj` 手工登记）：`Features/Family/ProfileView.swift`、`Features/Family/DueDateEditor.swift`、`Features/Family/MemberDetailView.swift`、`Features/Family/FamilyActivityView.swift`、`Features/Family/InvitationViews.swift`。
- `FamilyStore`：增加孕期、动态、邀请、成员详情的加载与操作。
- `AppSessionStore`：新增 `switchFamily(familyID:pregnancyID:)` 和 `familyNotice`；家庭变更（接受邀请、退出、被移出）后更新会话中的 `familyID` / `pregnancyID`。
- `PregnancySetupView`：顶部列出待处理邀请。
- 新的 `InvitationPromptStore`：主界面出现时查询 `me/invitations`，驱动逐条弹窗。
- `PregnancySetupModel`：增加「当前孕周」模式，供改预产期面板与建档页共用。

## 9. 出错与边界

- 两人同时改预产期：后保存的生效，两条都进动态。
- 接受时邀请已撤回、过期或已在该家庭：提示原因并刷新邀请列表。
- 移出已经离开的人：提示「TA 已经不在家庭里了」并刷新。
- 所有失败在当前面板内显示，不关闭面板。

## 10. 测试

- **后端集成测试**：改预产期（权限、范围、事件）；邀请（7 天、撤回、重发、按手机号查询、暂不后仍可接受）；`GET /me`；接受（原家庭有内容拒绝、无内容清理并加入）；退出、移出、管理员转移、新建空家庭；动态（合并排序、翻页、私密记录不出现、AIM 标注、已删除目标）；对话历史按家庭过滤；注销清理删除 `family_events`。
- **App 单元测试**：三种填法换算与范围检查；`FamilyStore` 新操作；邀请弹窗状态。
- **App UI 测试**：原有点「改我的信息」「隐私政策」「用户协议」「退出登录」「注销」的用例改为先进入个人资料；新增「A 邀请 B，B 注册后接受，进入 A 的家庭」。
