# 补缺口：孕期任务全程覆盖、危险信号扩充、孕周推进续任务 设计规格

2026-10-10

## 1. 问题

- **待办大部分孕周是空的。** `content/pregnancy-tasks/` 只有第 5–12 周（5 条）与第 18–19 周（4 条）。第 13 周以后建档的人，待办页基本是空的。
- **计划只在建档那一刻生成一次。** `POST /plan` 按当时孕周取模板生成任务，之后孕周推进不会补任何新任务——第 5 周建档的人到第 20 周，待办里仍只有孕早期那几条。
- **危险信号只有 2 条**（出血、高热）。胎动减少、破水、子痫前期征兆、早产宫缩、宫外孕信号、血栓、胆汁淤积等都没有。而且 iOS 自查只分「立即就医」与「下次产检告诉医生」两档，「一两天内要联系医生」（如手心脚心痒）被错误地归进「下次产检」。

## 2. 范围

做：第 4–42 周的待办模板内容；孕周推进时自动续上本周任务（不重复、不复活用户删掉的）；危险信号扩到约 16 条并加三档自查；Agent 与 App 都用到新的危险信号。

不做：按医院或个人情况定制任务；推送提醒（属「主动提醒」子项目）；危险信号的症状问诊流程。

### 3.2 写作约束

- 沿用现有 schema（`id`、`title`、`summary`、`due_in_days`、`source_type: template`、`priority`）；`id` 全局唯一，用 `<阶段>-<短名>`（如 `w25-ogtt-prep`）。
- 标题是一件具体能做的事（「预约糖耐量检查」），≤20 字；摘要 1–2 句，≤60 字，检查时间写「按医生安排」或给指南常见孕周。
- 与百科对应的任务，摘要里不放链接，但标题措辞与百科条目一致，方便用户在资料库找到。
- 杭州政策类任务只写「去哪里查、准备什么」，不写金额天数（沿用 ADR）。
- 文件头 `source` 写明依据（《孕前和孕期保健指南（2018）》等），`reviewed_at` 为审核日期；内容由 Claude 起草并对照指南自审（同百科的做法），审核记录写进 `content/README.md`。
- 契约测试：每个文件过 schema；所有模板 `id` 全局唯一；第 4–42 周每周至少有 1 个文件覆盖。

## 4. 孕周推进时续上本周任务

### 4.1 规则

- 用户打开待办或首页时，后端检查当前孕周：凡 `gestational_weeks` 包含当前孕周的模板文件，其中**该计划从未生成过**的条目，现在生成为任务（`source_type = template`、`source_id = 条目 id`、`changed_by_actor_type = system`、`due_at = 今天 + due_in_days` 的 09:00 UTC，与初始计划一致）。
- 「从未生成过」以新表 `plan_template_seeds(plan_id, template_id, seeded_at)` 为准，主键 `(plan_id, template_id)`。**用户删除了的模板任务不会被重新生成**，因为种子记录还在。
- 跳过的孕周不补：用户第 20 周才打开 App，第 13–17 周的模板不再生成（已过时）；只生成覆盖当前孕周的。
- 改预产期导致孕周变化时，按新孕周照常判断。
- 没有计划（从未生成）时不做任何事——初始计划仍由现有 `POST /plan` 负责。

### 4.2 实现

- 迁移 `0012_plan_template_seeds`：建表，并**回填**：现有每个计划里 `source_type = 'template'` 的任务，把 `(plan_id, source_id)` 写入种子表。
- `generate_initial_plan` 在创建模板任务时同时写种子。
- 新命令 `sync_week_tasks(pregnancy_id, as_of)`：读孕周 → 取覆盖该周的模板条目 → 过滤掉种子表已有的 → 逐条 `INSERT … ON CONFLICT DO NOTHING` 写种子，只有真正插入成功的才创建任务（防止两个并发请求重复生成）→ 提交。
- 调用点：`GET /api/v1/pregnancies/{id}/today` 与 `GET /api/v1/pregnancies/{id}/plan` 在读取前先调用 `sync_week_tasks`（幂等；只在有新任务时写库）。Agent 的 `list_tasks` 走同一路径的话一并覆盖；若 Agent 走独立查询，也在其入口调用。
- 失败不影响读取：sync 抛错时记日志并继续返回读取结果（续任务是锦上添花，不能让待办页打不开）。

### 4.3 家庭动态

系统自动续上的任务不写家庭动态（避免每周一早上刷屏）。

## 5. 危险信号

### 5.1 内容

`content/safety-rules/pregnancy-red-flags.yaml` 扩到 19 条，`severity` 三档，沿用后端领域代码已有的 `urgent / same_day / routine`（内容 schema 现写的是 `info / warning / urgent`，与领域代码不一致，统一改为前者）：

- `urgent`（立即就医/急救）：阴道流血量多或伴腹痛；20 周后任何阴道出血（37 周后少量带血黏液按见红处理）；孕早期一侧下腹剧痛、晕厥或肩痛（宫外孕信号）；破水或阴道持续流液；胎动明显减少、变弱或停止（28 周后另有「2 小时不足 10 次」的计数口径）；不足 37 周出现规律宫缩，或腰酸、下坠感一阵阵出现或越来越重；剧烈头痛、视物模糊、上腹痛（子痫前期信号）；抽搐或意识不清；胸痛、呼吸困难；单侧小腿持续肿痛、不像抽筋那样很快缓解，可能发红发热（血栓信号）；高热（≥38.5℃）；有伤害自己或宝宝的念头。
- `same_day`（今天或明天联系产检医院）：20 周前阴道少量出血或褐色分泌物、没有剧痛头晕（未经 B 超确认宫内孕的、或伴腹痛的，今天就联系）；体温 38.0–38.4℃，或 37.5℃ 以上一天没退，或伴咳嗽、腹泻、尿痛（今天就联系）；手脸突然明显水肿（血压 ≥140/90 今天就联系；高压 ≥160 或低压 ≥110、或伴头痛眼花时升为立即就医）；手心脚心明显瘙痒、夜间加重（胆汁淤积信号）；排尿疼痛、发热或腰痛（泌尿感染）；严重呕吐、吃喝不下、尿量明显减少；持续两周以上的情绪低落或焦虑。
- 新增可选字段 `weeks: [起, 止]`：只在相应孕周显示的规则（如宫外孕信号 [4, 13]、早产宫缩 [20, 36]、胎动减少 [24, 42]、破水 [16, 42]、20 周后出血 [20, 42]、孕早期少量出血 [4, 19]）。缺省为全程。
- same_day 的 `action` 第一句以「今天」开头（「今天或明天联系…」或「今天就联系…」），不写急诊或 120；后面可以加升档线（出现什么情况改为立即就医）。
- 每条 `condition` 用孕妇能自己判断的大白话，`action` 写具体动作（「立即去产科急诊或拨打 120」「今天联系你的产检医院」）。

### 5.2 iOS 自查三档

`SafetyCheck.Level` 增加 `soon`：勾中任一 urgent → `now`（「请立即联系产检医院或拨打 120」）；否则勾中任一 same_day → `soon`（「今天或明天联系你的产检医院」）；否则 `mention`。`soon` 的标题固定为「今天或明天联系你的产检医院」，是这一档的下限；勾中条目的 `action` 可以比标题更急（如「今天就联系」），结论下方逐条列出，以 action 为准。自查列表按当前孕周过滤 `weeks`（孕周先夹到 4–42），urgent 排在前面。

### 5.3 接口与 Agent

- `GET /api/v1/safety-rules?week=` 支持按孕周过滤（不传返回全部，向后兼容旧版 App）；响应条目加 `weeks`。
- Agent 目前读不到危险信号（只有指令里一句笼统的 red-flag）。`/internal/agent-tools/get-pregnancy-context` 的返回增加 `red_flags`：当前孕周适用的 urgent 与 same_day 条目（`condition`、`action`、`severity`）；指令要求：用户描述与 urgent 条目相符时，第一句就劝立即就医并照 `action` 说；与 same_day 相符时，建议今天或明天联系产检医院。

## 6. 测试

- 内容：新文件 schema；模板 id 全局唯一；4–42 周覆盖；危险信号 schema（含 `weeks` 合法）。
- 迁移：回填后现有计划的模板任务都有种子。
- 续任务：第 5 周生成的计划，孕周推进到第 25 周时调用 sync 只生成第 25–28 周文件的任务；再次调用不重复；删除其中一条后再 sync 不复活；没有计划时不报错；并发两次 sync 只生成一份（用唯一约束验证）；`GET /today` 与 `GET /plan` 会触发 sync，sync 抛错时两个接口仍返回 200。
- 危险信号：`?week=` 过滤；iOS `SafetyCheck` 三档判定与排序的单元测试。

## 7. 风险

- 在 GET 里写库：幂等、只在有新任务时写，且失败不影响读取；并发靠唯一约束兜底。
- 内容质量：同百科，对照指南自审并记录；危险信号宁可多报不漏报，但 same_day 不能写成「立即急诊」以免狼来了。
