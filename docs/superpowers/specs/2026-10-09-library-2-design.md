# 资料库 2.0 设计规格

2026-10-09

## 1. 问题

资料库现在用途很小：

- **空。** 8 月的知识条目规格把资料库定为「聊出来的」，删掉了预置内容。新用户进来大部分分类是空的，没有东西可看。
- **只能看。** 产检记录行点不开；产检只能手填体重和血压；知识条目改不了（PATCH 在知识条目上会因为没传 title 必然失败）；产检和身体感受页不显示知识条目，也没有「加一条」。
- **和 AIM 是两张皮。** AIM 只能用 `list_records` 一条条翻记录，读不到任何预置资料，回答里也不会指向资料库；在资料库里看到一条东西，没法顺着问下去。

## 2. 定位

资料库是两层：

- **孕期百科**：预置的、经人工审核的孕期知识，按主题和孕周组织。开箱就有内容，随孕周变化推荐。
- **我的档案**：关于这个家庭这次孕期的一切——报告与指标、身体感受、想问医生的问题、存下来的知识、AIM 记得的事。

AIM 两层都读：回答时引用百科和档案，并能往档案里写（报告、记忆、知识）。用户在任何一条资料上都能「问 AIM」。

## 3. 范围

做：百科（内容格式、首批内容、浏览）、AIM 翻目录并引用、从资料问 AIM、报告闭环、AIM 记得的事、档案的手动新增与编辑。

不做：搜索（用户端与 AIM 端都不做检索，AIM 改为翻目录）、收藏与已读标记、导出产检档案、向量检索、百科的用户评论或纠错入口。

## 4. 孕期百科

### 4.1 内容格式

新目录 `content/encyclopedia/`，一个主题一个文件（`checkup.yaml`、`diet.yaml`……），附 `schema.json`。文件头沿用现有约定：`id`、`version`、`source`、`source_url`、`reviewed_at`，新增 `review_status: draft | reviewed`。

条目字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 是 | 稳定编号，`<主题>.<短名>`，如 `checkup.ogtt`。发布后不改名，AIM 引用与客户端跳转都靠它 |
| `title` | 是 | 标题，≤16 字 |
| `aliases` | 否 | 口语别名，≤6 个，供 AIM 翻目录时对上用户的说法（「肚子发紧」→ 宫缩） |
| `weeks` | 否 | `[起, 止]`，适用孕周，4–42。缺省表示全程 |
| `summary` | 是 | 一句话，≤60 字 |
| `sections` | 是 | 1–4 段，每段 `heading` + `text`（≤300 字）。常用小节：是什么、为什么、怎么做、什么时候找医生 |
| `ask` | 是 | 2–3 个推荐问 AIM 的问题，每个 ≤24 字 |
| `related` | 否 | 相关条目编号 |
| `kind` | 否 | `policy` 表示政策类：只给办理入口与官方链接，正文不得给出金额、资格等结论（沿用 ADR 原则） |
| `link` | 否 | 官方链接，`kind: policy` 时必填 |

### 4.2 主题

| 主题 `id` | 名称 | 首批约 |
| --- | --- | --- |
| `checkup` | 产检项目 | 14 条（建档、NT、唐筛/无创、大排畸、糖耐量、胎心监护……） |
| `body` | 身体变化与不适 | 14 条（孕吐、腰酸、水肿、抽筋、便秘、失眠、宫缩辨别……） |
| `diet` | 饮食营养 | 12 条（并入现有 `content/nutrition` 的 7 条，补体重增长、补铁补钙、控糖……） |
| `life` | 生活与运动 | 8 条（运动、出行、工作、性生活、用药原则……） |
| `birth` | 待产与分娩 | 8 条（产兆、什么时候去医院、分娩方式、待产包……） |
| `paperwork` | 办事与政策 | 4 条，全部 `kind: policy`（建档建册、生育津贴、陪产假、出生一件事） |

约 60 条，要求第 4–40 周每一周至少有 2 条 `weeks` 覆盖到。

`content/nutrition` 并入 `diet` 后删除该集合；`content/preparation`（待产包清单）与 `content/hangzhou`（办事清单）是带勾选状态的清单，不是文章，**保持不变**，在 `birth` 与 `paperwork` 主题页下方继续显示。`content/safety-rules` 保持独立。

### 4.3 生产与审核

由 Claude 依据公开权威资料离线起草（中华医学会妇产科学分会《孕前和孕期保健指南》、《中国居民膳食指南（2022）》孕期妇女部分、国家卫健委公开的孕产期保健与母婴健康素养资料），每个文件 `review_status: draft`。产品负责人逐文件审核，改为 `reviewed` 并填写 `reviewed_at`。

**草稿不上线**：API 默认只加载 `reviewed` 文件；环境变量 `AIM_CONTENT_INCLUDE_DRAFTS=1` 时才加载草稿（本地开发与模拟器打开，生产不开）。

写作约束：平实、不吓人、不诊断；剂量、检查时间一律写「按医生安排」或给出指南原文的常见范围并注明「以医生意见为准」；每条 `sections` 里凡涉及症状，都要有「什么时候找医生」。

### 4.4 接口

- `GET /api/v1/library/encyclopedia?topic=&week=`：目录。返回主题列表（名称、条目数）与条目摘要（`id`、`topic`、`title`、`aliases`、`weeks`、`summary`）。传 `week` 时只返回覆盖该周的条目，按 `weeks` 起点与当前周的接近程度排序。
- `GET /api/v1/library/encyclopedia/{id}`：单条全文。不存在返回 404。
- 内容在进程启动时加载并校验一次，缓存在内存里（现有内容接口每次请求都重读文件，百科不沿用这个做法）。校验失败启动报错。

### 4.5 校验

`services/api/tests/contract/content/` 新增百科的 schema 测试，并补上现在漏掉的 `nutrition`（删除前）与 `preparation`。另加一致性测试：`id` 全局唯一、`related` 指向存在的条目、`id` 前缀等于所在主题、`kind: policy` 必须有 `link`、第 4–40 周覆盖（只对 `reviewed` 文件计算；全是草稿时跳过覆盖检查）。

## 5. 我的档案

继续复用 `records` 表，不加新表。

### 5.1 编辑

- 修好 `update_record` 漏传 title 的问题。
- 编辑权限：家庭可见的记录，家里任何成员都能改；仅自己可见的记录只有作者能改。与「家里任何成员可改预产期」一致。
- 不加乐观锁：记录由人改、并发极低；AIM 不改已有记录（记忆的删除走单独工具，见 7.4）。

### 5.2 产检报告

仍是 `checkup` 记录，原图用现有的 `attachment_refs`。`structured_data` 调整：

- `hospital`、`exam_items`、`result`、`doctor_advice` 改为可选（报告单上常常没有医嘱）。
- `metrics` 白名单新增 `fetal_heart_rate`（次/分，100–200）、`fundal_height_cm`（10–45）。这两项每次产检都测，值得画趋势。
- 新增 `other_items[]`：报告上的其他化验项，每项 `name`（必填）、`value`（必填，字符串，保留原样如「阴性」「5.2」）、`unit`、`reference`（参考范围原文）、`flag`（`high | low | abnormal | null`）。最多 60 项。只展示、不画趋势。

### 5.3 AIM 记得的事

新记录类型 `memory`。`structured_data`：`kind`（`allergy` 过敏 / `history` 病史与既往孕产史 / `medication` 在用药物 / `care` 医院医生与产检安排 / `preference` 偏好 / `other`）、`text`（≤80 字，必填）。`title` 由 `text` 截取。

默认家庭可见（整个 App 是家庭视角：爸爸问 AIM 时也该知道妈妈对什么过敏），用户可以逐条改成仅自己可见。每个家庭最多 50 条有效记忆，超出时拒绝新增并提示先整理。

### 5.4 手动新增

- **产检/报告表单**重做：日期、医院、白名单指标（全部 7 项，选填）、其他化验项（逐行加：名称、数值、单位、参考范围、是否异常）、照片（最多 9 张，走现有附件上传）、结果与医嘱。
- **记忆**：选类型 + 一句话。
- 已有的症状、问题、笔记、知识表单增加编辑模式（同一个表单，带入原值）。

## 6. 资料库页面

自上而下：

1. **顶部**：沿用公共顶部组件，标题「资料库」，副标题「孕 31 周 · 百科 60 条 · 我的 34 条」，右侧 AIM 按钮。
2. **这周读什么**：横向滑动的 3–5 张卡片，取覆盖当前孕周的百科条目，显示主题色标签、标题、摘要。这是让资料库随孕期变化、不再死板的主要位置。
3. **本周关注**：沿用现有规则，新增一条最高优先级规则——最近一份报告里有 `flag` 非空的项目，且未被加入「想问医生」：「最近报告有 2 项异常，记得问医生」，点击进报告详情。
4. **我的档案**：网格卡片，延续现有活数据卡片样式——产检与报告（最近一次日期、指标迷你趋势、异常项数）、身体感受、想问医生、AIM 记得的事（条数 + 最近一条）、我存的知识（知识条目与笔记）。
5. **孕期百科**：六个主题卡（图标、名称、条目数、「本周相关 N 条」）。
6. **危险信号**通栏，保持不变。

现有七个分类的去向：产检与指标 → 档案「产检与报告」；身体感受、想问医生 → 档案；吃什么 → 百科 `diet`（用户存的菜谱、能不能吃等知识条目在「我存的知识」里，`diet` 主题页底部也列出分类为饮食的知识条目）；办事指南 → 百科 `paperwork`（下方保留办事清单）；待产准备 → 百科 `birth`（下方保留待产包清单）；危险信号不变。知识条目的 `category` 取值不变（`nutrition` 等仍合法），只是展示位置随之调整，不迁移数据。

### 6.1 百科条目详情

标题、主题标签、适用孕周、摘要、各小节、「问问 AIM」的 `ask` 问题（点一个即切到 AIM 并自动发送，沿用首页本周详情的「打开即发送」机制）、相关条目、页脚来源与核对日期。政策类条目显示官方链接按钮与「以官方最新规定为准」。

### 6.2 主题页

列出该主题全部条目，覆盖当前孕周的排在前面并标注「本周」。

### 6.3 报告详情

日期、医院、照片缩略图（沿用记录详情的图片查看）、白名单指标与上一份报告对比（「↑ 0.8 kg」）、其他化验项列表（异常项标色并排在前）、结果与医嘱。底部操作：编辑、问 AIM（带上这份报告）、把异常项加入想问医生。产检列表的记录行改为可点击进入此页。

### 6.4 AIM 记得的事

按 `kind` 分组列出；每条可编辑、删除、切换可见性；顶部说明「AIM 会在每次对话开始时读到这些，帮你回答得更贴切。你可以随时修改或删除。」右上角「+」手动添加。

### 6.5 从资料问 AIM

百科条目、报告、指标趋势、症状统计、记忆页都有「问 AIM」。它带上 `AgentContext`：标题写明类型与名称（「百科：糖耐量检查」「报告：10月3日 产检」），摘要包含编号（百科 `id` 或记录 `id`）与一句话摘要，AIM 需要全文时自己调工具读。

## 7. AIM 联动

### 7.1 翻目录：两个只读工具

- `list_library({ topic?, week? })` → 调 `/internal/agent-tools/list-library`，返回目录（同 4.4，不含正文）。
- `get_library_entry({ id })` → 返回单条全文。

两者都登记为只读工具（`READ_ONLY_TOOLS`、`TOOL_TITLES`、`runtime-gate` 测试、`instructions.md` 的读工具列表）。`list_records` 的 `type` 放开到 `question`、`knowledge`、`memory`。

### 7.2 引用

指令要求：回答孕期知识类问题前，先 `list_library` 看目录、`get_library_entry` 读相关条目，以百科内容为依据回答；用到某条时在句末写 `[[ref:<id>|<标题>]]`；引用档案里的记录写 `[[record:<uuid>|<标题>]]`。只能引用本轮工具返回过的编号。百科没有覆盖的问题可以照常回答，但不得编造引用。

`agent-web` 的 `MarkdownText` 在 `renderInline` 里识别这两种标记，渲染成行内来源胶囊（书本图标 + 标题），点击走 `openNative`，新增 `kind: encyclopedia`（`id` 为条目编号）；`record` 已有。格式不合法的标记原样去掉方括号显示标题。iOS 端 `AgentWebRoute` 与 `AgentDestinations` 增加百科条目的跳转；条目不存在时显示「这条资料已下线」。

### 7.3 报告闭环

新工具 `create_checkup_report`，**执行前确认**（`approval: always()`，不进 `DIRECT_EXECUTION_TOOLS`）。参数：`date`、`hospital?`、`metrics?`（白名单）、`other_items?`、`attachment_ids`（本轮图片编号）、`result?`、`doctor_advice?`、`follow_up_questions?`（≤5 条，每条 ≤60 字）。

流程：用户拍报告进 AIM（现有链路）→ 模型读图 → 调用此工具 → `agent-web` 渲染新的报告预览卡：日期与医院、指标表（异常项标色）、将同时创建的「想问医生」问题列表、提示「看不清的项目没有填，请核对后确认」→ 用户确认 → API 在一个事务里创建 `checkup` 记录与 `question` 记录（问题的 `structured_data` 带 `report_id` 指回报告）→ 卡片「查看」跳到报告详情。

指令约束沿用读图规则：看不清的值不填、不猜；`flag` 只按报告单上的标记或参考范围判断，不做医学解读；异常项的追问写成「想问医生的问题」，不写成结论。

撤销：确认后写入的报告与问题支持 `undo_operation` 整批撤销。

### 7.4 记忆

- `remember({ kind, text })`：**直接执行、可撤销**（与 `create_record` 同档，API 侧加入 `DIRECT_EXECUTION_TOOLS`）。聊天里显示一张小卡「已记住：对青霉素过敏」，带撤销。
- `forget_memory({ id })`：**执行前确认**，用于用户说「我不再吃那个药了」这类情况。

记什么由指令约束：只记稳定、对以后的对话有用的事实（过敏、病史、在用药物、产检医院与医生、明确表达的偏好）；不记一次性的状态（「今天有点累」）、不记症状（症状走 `symptom` 记录）；用户明确说「别记这个」时不记；记之前不用问，记完告诉用户记下了什么。

注入：新增 `services/agent/agent/instructions/memory.ts`，`defineDynamic` 在 `session.started` 时用 `ctx.session.auth` 取作用域，调 `/internal/agent-tools/list-memories`，返回一段系统指令：「关于这个家庭，你记得：……（按类型分行）」。没有记忆时返回 `null`。取失败时记一条日志并返回 `null`，不阻断会话——模型仍可用 `list_records(type=memory)` 自己读。会话中途新增的记忆，模型本来就在上下文里知道。

可见性：注入与 `list_records` 都按当前账号可见的记录过滤（家庭可见 + 自己的私有）。

## 8. 分期

每期独立可验收、可上线：

1. **百科底座**：内容格式、schema 与一致性测试、草稿开关、两个接口、首批约 60 条草稿；iOS 资料库新布局（这周读什么、我的档案、孕期百科三区）、主题页、条目详情（含「问问 AIM」）；`nutrition` 并入。
2. **AIM 翻目录与引用**：`list_library`、`get_library_entry`、`list_records` 放开类型、指令、引用标记渲染、`encyclopedia` 原生跳转；所有资料页的「问 AIM」上下文。
3. **档案可编辑与报告闭环**：PATCH 修复与权限、`checkup` 结构调整、报告表单与报告详情、`create_checkup_report` 与预览卡、本周关注新规则。
4. **AIM 记得的事**：`memory` 类型与校验、`remember` / `forget_memory`、会话开始注入、记忆页与手动表单。

## 9. 测试

- **API**：百科加载、草稿开关、目录按主题与孕周过滤和排序、单条 404；百科 schema 与一致性；`checkup` 新字段校验（`other_items` 缺字段、超 60 项、`flag` 非法、新指标越界）；`memory` 校验与 50 条上限；PATCH 知识条目成功、家庭成员可改家庭可见记录、不能改他人私有记录；`create-checkup-report` 一次创建报告与问题、需要 `approved`、整批撤销；`list-memories` 只返回可见记录。
- **Agent**：新工具登记进 `runtime-gate`；`create_checkup_report`、`forget_memory` 带 approval，`remember` 不带；记忆注入在无记忆、取失败时返回 `null`。
- **Web**（vitest）：引用标记解析（合法、缺标题、嵌套在粗体里、非法格式）；报告预览卡渲染异常项与问题列表；`remember` 小卡。
- **iOS**：单元——资料库快照摘要（这周读什么排序、本周关注新规则、档案卡空态）；百科与报告 DTO 解码。UI——资料库三区可达；打开百科条目并点「问问 AIM」切到 AIM；产检记录行可进报告详情；新增一条记忆后出现在记忆页。（已知有两条既有 UI 用例失败，与本项无关。）

## 10. 风险

- **百科内容质量**：错一条比没有更糟。用草稿开关把关，审核前不上生产；每条带来源与核对日期；指令要求 AIM 以百科为依据但不替代医生。
- **引用编号幻觉**：模型可能编造 `id`。限制为「只能引用本轮工具返回过的编号」，客户端对不存在的编号显示「这条资料已下线」而不是报错。
- **记忆误记**：直接执行降低了摩擦，靠「已记住」小卡、撤销与记忆页的可见可删兜底。
