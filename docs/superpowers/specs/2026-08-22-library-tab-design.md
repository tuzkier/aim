# 资料库：孕期信息的统一入口

日期：2026-08-22

## 问题

孕期产生的信息现在无处安放，或者放了但看不见：

- 记录（症状 / 产检 / 备忘）混在时间线里，按时间排列。想回答「我这三次血压分别是多少」只能一路往回翻。
- 内容库 `content/hangzhou`（生育福利）和 `content/safety-rules`（危险信号）**在 App 里没有任何入口**。数据写好了，用户看不到。
- 孕期真实存在但系统里完全没有的：想问医生的问题、待产准备清单、饮食参考。

## 目标

一个第四个 Tab「资料库」，装下所有孕期相关的事情：我记下来的、需要长期盯的、随时要查的。
与 Agent 双向打通——Agent 能往里写，也能带某个分类的上下文发起对话。

## 界面

**不是列表。** 每张分类卡承载活数据，扫一眼就知道哪里有新东西：

```
资料库                          [搜索] [AIM]
孕 18 周 · 已收录 34 条

┃ 本周关注
┃ 血压连续两次偏高，下次产检记得带上记录问医生
┃ [指标 2 条] [待问医生]

┌──────────────┐ ┌──────────────┐
│ 产检与指标    │ │ 吃什么        │
│ 8 次 · +6.2kg │ │ 食谱 12 · 禁忌 │
│ ▁▃▂█ (趋势)   │ │ 补铁：菠菜猪肝 │
└──────────────┘ └──────────────┘
┌──────────────┐ ┌──────────────┐
│ 身体感受      │ │ 想问医生      │
│ 近 7 天 4 条  │ │ 攒了 3 个问题  │
│ [腰酸×3][恶心]│ │ 能继续游泳吗？ │
└──────────────┘ └──────────────┘
┌──────────────┐ ┌──────────────┐
│ 办事指南      │ │ 待产准备      │
│ 建卡已完成    │ │ 待产包 6/22   │
│ ▰▰▱▱ (进度)   │ │ 32 周再备齐   │
└──────────────┘ └──────────────┘

⚠ 危险信号  出现这些情况立即就医        ›
```

- **本周关注**是唯一动态位，回答「我现在最该看什么」，由指标异常、待复查、Agent 产出驱动。
- **危险信号**单独通栏，不参与网格——它是安全兜底，不该和食谱平级。
- 右上 wand 按钮带当前分类上下文发起 Agent 对话，与时间线头部同一套机制。

## 数据来源

关键约束：六个分类的数据成熟度差别很大。

| 分类 | 数据来源 | 需要新建 |
| --- | --- | --- |
| 身体感受 | 现有 `symptom` 记录 | 无 |
| 危险信号 | 现有 `content/safety-rules` | 仅入口 |
| 产检与指标 | 现有 `checkup` 记录 | 指标趋势：结构化字段 + 趋势查询 |
| 办事指南 | 现有 `content/hangzhou` | 每项的完成状态 |
| 吃什么 | 无 | 新内容库 `content/nutrition` |
| 想问医生 | 无 | 新记录类型 `question` |
| 待产准备 | 无 | 新内容库 + 完成状态 |

**设计决定：能用记录就不新建表。**
「想问医生」加成 `RecordType.question`，复用记录的增删查、可见性、Agent 工具——
`create_record` 已经能写它，不需要新的工具。问题的「已解答」状态放 `structured_data`。

「办事指南」「待产准备」的完成状态同理：内容库提供条目清单，用户的勾选状态存成
`checklist` 类型的记录，`structured_data` 里带 `content_id` 与 `done`。
这样两个分类共用一套机制，且天然获得 Agent 写入能力。

## 分类目录是数据，不是代码

分类不写死在视图里，用一份声明式目录描述：标题、图标、数据源、摘要如何计算。
新增一个分类应该是加一条配置，不是改 `LibraryView`。

## 与 Agent 打通

- **写入**：已有的 `create_record` 覆盖 症状 / 备忘 / 问题 / 清单勾选。
  新增 `create_checkup`（带指标）——现有 `create_record` 的 `structured_data` 够用，
  暂不新增工具，先验证模型能否正确填充。
- **读取**：新增 `list_library` 工具？**不做**。`list_records` + `get_guidance` 已经覆盖，
  多加一个只读工具只会增加模型的选择负担。
- **上下文**：进入某个分类后调起 Agent，`AgentContext` 带上分类名与摘要。

## 分期

一次做完六个分类风险太大。按数据成熟度分三步，每步都可独立验收：

**第一步 · 骨架与现成数据**
资料库 Tab、分类目录机制、卡片墙布局、危险信号入口、身体感受、产检记录（不含趋势）。
全部基于现有数据，不动后端。

**第二步 · 新记录类型**
`RecordType.question` 与 `checklist`，想问医生、办事指南、待产准备三个分类。
后端加类型与校验，内容库加 `content/preparation`。

**第三步 · 派生数据**
指标趋势（产检结构化字段 + 趋势计算）、吃什么内容库、本周关注的驱动规则。

## 测试

- 单元：分类目录的摘要计算（空数据、单条、多条）；`question` / `checklist` 的记录校验。
- UI：资料库 Tab 可达；六张分类卡渲染；点进身体感受能看到已有症状记录；
  危险信号可打开。
- 后端：新记录类型的创建与校验；`create_record` 能写入 `question`。

## 不做什么

- 不做搜索的后端实现（第一步只放入口，本地过滤）。
- 不把家庭并入资料库——底部保留四个 Tab（已确认）。
- 不新增只读 Agent 工具。
