# iOS 孕期时间线交互与视觉重设计规格

## 1. 目标

当前 iOS 客户端功能闭环已经跑通，但交互与视觉停在“能用”的阶段：暖色设计语言因为 List 背景遮挡实际从未生效，深色模式下白底白字不可读，Agent 的产出说完即消失、无法回溯也无法撤销，任务缺少让家庭协作成立的负责人与来源信息。

本次重设计把“今天 / 计划 / 记录”三个页面合并为一条以孕周为刻度的连续时间线，把已确认的暖米色与陶土色从四个散装 `Color` 升级为完整的设计 token 体系，并按产品文档 §10 的三档执行权限补齐 Agent 的确认、告知与撤销机制。

本次范围只覆盖 iOS 客户端的交互与视觉。后端契约、Eve Runtime 与业务领域模型不在范围内；若时间线所需字段（任务负责人、变更来源）当前 API 未返回，按第 10 节的降级策略处理，不在本规格内改动服务端。

## 2. 已确认的产品决策

- 采用“连续时间线”方向，而非强化现有的聚焦式首页。已知代价：偏离当前实现最远、需拆除记录 Tab、工程量最大，用户在明确知晓后确认采用。
- 底部导航从四个 Tab 收敛为三个：`孕期`、`Agent`、`家庭`。
- 记录不再拥有独立 Tab，其内容并入时间线，其创建入口移至时间线头部。
- 沿用原型已确认的暖米色 + 陶土色方向，不重新定调，但升级为完整 token 体系并补齐深色模式。
- 强调色采用原型的陶土橙 `#BC5F3A`，而非当前代码中偏玫红的 `#C7545A`。
- Agent 保留对话形态并作为一级 Tab，但对话不再是产物：所有变更必须落回时间线并标记来源。
- 产品文档 §10 的三档执行权限分别映射到三种独立 UI。
- 全局悬浮 Agent 按钮取消，改为时间线头部的圆形入口。

## 3. 方案选择

### 3.1 为什么是时间线

孕期本身就是一条有确定刻度（40 周）、有确定方向（不可逆）、有确定锚点（今天）的时间序列。原有的“今天 / 计划 / 记录”三分法把同一条时间线切成三段，用户需要自己在脑内拼接：今天的事在今天页，下周的事在计划页，上周发生的事在记录页。

合并后，“已发生”与“将发生”在同一个滚动容器里连续，孕周分组头提供绝对定位感。这也与产品文档 §5.8“形成连续的家庭时间线”一致。

### 3.2 为什么保留 List 而不换 ScrollView

时间线需要自绘导轨和背景，直觉上应当换成 `ScrollView + LazyVStack`。本规格选择继续使用 `List`：

- 导轨画在 `.listRowBackground` 中，每行背景绘制一条贯通自身高度的竖线，行间自然连成一条连续导轨；
- `.scrollContentBackground(.hidden)` 让暖色底透出，顺带修复当前版本暖色背景被系统 List 背景遮挡的缺陷；
- `.listRowSeparator(.hidden)` 关闭系统分隔线，由设计自行控制。

保留 `List` 换来 `swipeActions`、`refreshable`、键盘规避、Section header 吸顶与 VoiceOver 遍历顺序全部由系统负责。自绘方案视觉自由度更高，但上述能力需逐项重做，其中滑动操作与 VoiceOver 顺序尤其容易做砸。

## 4. 信息架构

### 4.1 Tab 结构

| Tab | 图标 | 承载 |
| --- | --- | --- |
| 孕期 | `timeline.selection` | 时间线：任务、记录、孕周节点 |
| Agent | `wand.and.sparkles` | 对话、最近处理台账、撤销入口 |
| 家庭 | `person.2` | 成员、分工、邀请、孕期档案 |

### 4.2 记录 Tab 的拆解去向

- **查看**：记录作为“已发生的事实”，落在时间线上其 `occurredAt` 对应的位置，与已完成任务并排。
- **创建**：时间线头部常驻 `+` 按钮，弹出记录 composer，沿用现有 `RecordComposerView` 的表单结构，仅替换视觉。
- **按类型筛选**：从 Tab 内的 segmented control 改为时间线头部的筛选按钮，详见 §5.6。

### 4.3 时间线结构

```
↑ 过去（向上分页加载）
  孕 17 周 · 8月4日–10日      ← 分组头，吸顶
    已完成任务（删除线 + 降透明度）
    记录（正常色，不降透明度）
  ...
  今天                          ← 唯一使用强调色的分组头
    焦点卡（现在最重要 + 主行动按钮）
    今日其余任务
  孕 19 周 · 8月18日–24日
    计划任务
  孕 20 周 · 大排畸             ← 4 周之外仅显示阶段摘要行，点击展开
↓ 未来
```

- 分组刻度一律为孕周，不使用自然日期分组。
- 未来方向近 4 周默认展开，更远只显示阶段摘要行。
- 过去方向初始加载 4 周，向上滚动分页。

### 4.4 今天的锚定

1. 启动时 `ScrollViewReader.scrollTo(.today, anchor: .top)`，不带动画，用户不应看到滚动过程。
2. 今天是唯一使用强调色分组头与实心锚点的一段。
3. 滚离超过两屏后，底部浮出「回到今天」胶囊按钮。

### 4.5 任务与记录的视觉区分

任务可操作，记录是既成事实，二者必须一眼可分：

| | 任务 | 记录 |
| --- | --- | --- |
| 左侧元素 | 圆形 checkbox，可点击 | 类型图标，不可点击 |
| 元信息 | 负责人 · 时间 · 来源 | 类型 · 关键值（如「程度 2」） |
| 过去态 | 删除线 + `textTertiary` | 保持 `textPrimary`，不降透明度 |

记录不因为“已经过去”而显得次要。

## 5. 视觉设计

### 5.1 语义色 token

深色模式的底色是暖黑而非系统中性黑，色温必须保住，否则 App 的性格在深色下丢失。

| token | Light | Dark | 用途 |
| --- | --- | --- | --- |
| `canvas` | `#F6F1E9` | `#1A1714` | 页面底 |
| `surface` | `#FFFDF9` | `#232019` | 卡片 |
| `surfaceRaised` | `#FFFFFF` | `#2C2822` | sheet、toast |
| `surfaceSunken` | `#F8F3EA` | `#1F1C17` | diff 卡内底 |
| `separator` | `#EBE3D6` | `#38322A` | 分隔线、卡描边 |
| `rail` | `#DFD6C6` | `#443D33` | 时间轴导轨 |
| `textPrimary` | `#2C2620` | `#F0EAE0` | 正文 |
| `textSecondary` | `#837A6E` | `#A79D8F` | 元信息 |
| `textTertiary` | `#ABA192` | `#7A7164` | 孕周头、已完成 |
| `textOnAccent` | `#FFF8F3` | `#FFF8F3` | 陶土底上的文字 |
| `accent` | `#BC5F3A` | `#D97D52` | 陶土，主操作 |
| `accentSoft` | `#F5E5DC` | `#3A2A21` | 标记底、锚点光环 |
| `success` | `#6B7F4E` | `#9BB07A` | 已完成 |
| `successSoft` | `#EDF0E6` | `#2A3020` | 安全声明底 |
| `danger` | `#B4442F` | `#E08066` | 医疗红旗、破坏性操作 |
| `dangerSoft` | `#F7E6E1` | `#3A241D` | 错误态底 |

深色的 `accent` 由 `#BC5F3A` 提亮至 `#D97D52`：原色在暖黑底上对比度约 3.1:1，不满足 WCAG AA。

全部 token 以 colorset 形式进入 `Assets.xcassets`，带 Any / Dark 两档外观。`AimTheme` 退化为类型安全的引用层，不再出现硬编码的 `Color(red:green:blue:)`。

### 5.2 强调色配额

陶土色一屏最多出现四处：主行动按钮、今天锚点、`Agent 调整` 来源标记、记录类型图标。其余一律中性暖灰。

当前实现把 accent 用在每个任务的圆圈和每个 Label 图标上，导致它不再具备强调功能。

### 5.3 分层策略

不使用阴影分层，靠色温分层：`canvas` → `surface` → `surfaceRaised` 三层色差很小但同为暖调，观感是“浮起”而非“框住”。仅 sheet 与 toast 使用极轻阴影表达脱离页面平面。

### 5.4 字阶

一律使用相对字体以支持 Dynamic Type，禁止 `.system(size:)`。

| token | SwiftUI | 用途 |
| --- | --- | --- |
| `display` | `.largeTitle.weight(.medium)` | 孕周大标题 |
| `title` | `.title3.weight(.medium)` | 焦点卡、sheet 标题 |
| `body` | `.body` | 任务标题 |
| `callout` | `.subheadline` | 说明文字 |
| `meta` | `.footnote` | 负责人 · 时间 · 来源 |
| `label` | `.caption2` + `.tracking(0.9)` | 孕周头、小标签 |

### 5.5 几何

- 间距：`4 / 8 / 12 / 16 / 20 / 28`
- 圆角：`13` 按钮、`15` toast 与小卡、`16` diff 卡、`20` 焦点卡、`28` sheet 顶角
- 导轨：左边距 `27`，线宽 `1`；圆点 `9`（过去与未来，空心 `1.5` 描边）/ `13`（今天，实心 + `4` 光环）
- 过去段导轨实线，未来段虚线

### 5.6 头部

大标题为「孕 18 周 + 3 天」，日期降为其上方的陶土色小字。时间线的主语是孕期进程，不是日历日期。

右侧三个 32pt 圆形按钮，自左至右：筛选（`line.3.horizontal.decrease`，中性）、`+`（新增记录，中性）、`wand`（Agent，陶土软底）。

筛选按钮弹出 `Menu`，选项为「全部 / 待办 / 产检 / 身体感受 / 随手记」，默认「全部」。选中非全部时按钮变为陶土色以示当前处于筛选状态。

Agent 圆形按钮与 Agent Tab 并存且用途不同：按钮带当前时间线上下文发起提问，是快捷入口；Tab 是完整的对话与台账界面。按钮打开的仍是同一个 Agent 界面，只是预置了上下文。

## 6. Agent 交互机制

### 6.1 三档权限映射

| 档位 | 场景 | UI | 撤销 |
| --- | --- | --- | --- |
| 直接执行 | 建普通待办、整理记录、生成清单、形成总结 | 无打断；时间线直接出现，带 `Agent 调整` 来源标记 | 走任务自身的删除 |
| 执行后告知 | 重新排期、调整优先级、分配普通家庭事项 | 深色 toast，停留 5 秒 | toast 上的「撤销」 |
| 执行前确认 | 医疗处置、用药、付费、购买、预约、取消服务、隐私分享及不可逆操作 | diff 确认 sheet | 不适用：未确认即未执行 |

### 6.2 diff 确认 sheet

自上而下的结构：

1. 标题「确认计划变更」+ 副标题「先确认 Aim 理解得对，再决定是否写入家庭计划。」
2. `我理解的是` 小标签 → Agent 对意图的复述（`title` 字阶）→ 一句定性说明（如「这是日程变化，不涉及新的医疗判断。」）
3. `计划将这样变化` 小标签 → diff 卡片，每行为「图标 + 字段名 + 旧 → 新」；超过三行折叠为「还有 N 项」
4. 安全声明条（`successSoft` 底）
5. 主按钮「应用 N 项变更」+ 文字按钮「暂不修改」

“我理解的是”这一段是本节的关键。用户否决 Agent 的原因通常不是变更本身，而是理解错了；当前实现只提供 `request.prompt` 一行文字，用户无从判断。

安全声明为固定文案，由客户端硬编码，不接受模型生成的内容 —— 它是产品承诺，不能让模型有机会改写。

sheet 使用 `.presentationDetents([.large])`，不允许中间态，避免关键信息被折叠。

### 6.3 撤销

- toast 停留 5 秒，包含图标、文案、「撤销」按钮与关闭按钮。
- 撤销能力本身不限时：toast 消失后，Agent Tab 的「最近处理」台账中每条记录仍可撤销。toast 只是把最近一次撤销提到手边。
- 撤销调用现有的 `undo_operation` 工具。

### 6.4 结果落回

所有 Agent 产出必须写回时间线并标记来源。被 Agent 创建或修改的任务，其元信息行追加 `Agent 调整`（陶土色）。

这是本方向相对当前实现最实质的改变：现在的对话说完即消失，用户无法知道“它到底改了什么”。

### 6.5 修复 initialDraft 失效

`RecordDetailView` 的「让 Agent 分析当前记录」当前已失效：`AgentSheet(initialDraft:)` 把文本写入 `store.draft`，但 ExyteChat 的 `ChatView` 自持输入状态且无预填 API，`store.draft` 唯一读取点是 send 回调，进入即被覆盖。

新方案不依赖预填输入框：该入口直接以该记录为上下文**发起一轮对话**，用户进入时看到的是已发出的问题和正在生成的回答，而不是一个待发送的草稿。

## 7. 空态、错误与反馈

### 7.1 状态优先级

每个页面按固定顺序判定，不得把错误当成空态展示：

```
未配置孕期 → 引导态
加载中且无缓存 → 骨架屏
加载失败且无缓存 → 错误态（含重试）
加载失败但有缓存 → 展示缓存 + 顶部错误条（含重试）
成功且无数据 → 空态（含主行动）
成功且有数据 → 内容
```

当前 `PlanView` 在网络失败时展示「还没有计划」且无重试入口，`RecordsView` 空态中的 `store.errorMessage ?? ...` 为不可达的死代码，均按上表纠正。

### 7.2 失败必须可见

- 所有 sheet 内的提交失败，错误必须显示在 sheet 内部，不能显示在被覆盖的底层页面。当前 `TaskDetailView` 的延期 sheet 与 `FamilyView` 的邀请 sheet 均违反此项。
- 所有提交按钮在进行中必须显示 loading 并禁用。当前邀请 sheet 的 `isSubmitting` 未驱动任何 UI。

### 7.3 触觉反馈

使用 `.sensoryFeedback`：

| 操作 | 反馈 |
| --- | --- |
| 完成任务 | `.success` |
| 应用 Agent 变更 | `.success` |
| 撤销 | `.impact(weight: .light)` |
| 保存记录 | `.success` |
| 提交失败 | `.error` |

### 7.4 转场

Agent 与各 sheet 的呈现统一为 `.sheet` / `.fullScreenCover`，不使用 ZStack 手动覆盖。当前 `AgentSheet` 在 `MainTabView` 走 ZStack 覆盖、在 `RecordDetailView` 走 `fullScreenCover`，两套呈现方式的动画与关闭手势不一致，且 ZStack 方案没有转场动画。

## 8. 页面规格

### 8.1 孕期（时间线）

- 头部：日期小字 + 孕周大标题 + `+` 与 Agent 两个圆形按钮
- 主体：如 §4.3
- 焦点卡：`现在最重要` 小标签 + 任务标题 + 说明 + 满宽主行动按钮。当前实现的优先事项卡整卡为 NavigationLink 而无明确行动出口
- 任务行滑动操作：右滑完成，左滑延期
- 下拉刷新重新拉取当前可见窗口
- 底部为「回到今天」浮出按钮预留 `safeAreaPadding`，避免遮挡最后一行

### 8.2 Agent

- 上半部：对话流，沿用 ExyteChat，但替换 `ChatTheme` 为本 token 体系
- 空态：恢复迁移时丢失的快捷提问 chips
- 生成中：恢复「停止生成」入口，调用当前无调用点的 `AgentStore.stop()`
- 失败态：错误卡片含重试按钮，不再是 `betweenListAndInputViewBuilder` 中的一行小字
- 下半部：`最近处理` 台账，每条含时间、变更摘要、来源与撤销入口

### 8.3 家庭

沿用现有结构，替换视觉，并补齐邀请流程的错误显示与 loading 态。成员行增加待办计数（如「爸爸 · 3 项待办」），与时间线的负责人信息形成闭环。

## 9. 无障碍

- Dynamic Type：全部文本使用相对字体；焦点卡与任务行在 `AX5` 尺寸下改为纵向堆叠
- VoiceOver：任务行合并为单一元素，朗读顺序为「状态 → 标题 → 负责人 → 时间 → 来源」；导轨与分组头装饰元素标记 `.accessibilityHidden(true)`
- 对比度：全部 token 组合满足 WCAG AA（正文 4.5:1，大字 3:1）
- 减少动态效果：开启 `reduceMotion` 时，「回到今天」改为瞬时跳转，toast 改为淡入淡出
- 保留现有 UI 测试依赖的 `accessibilityIdentifier`，并为时间线新增 `timeline-today-anchor`、`timeline-week-header-{week}`、`agent-diff-sheet`、`agent-undo-toast`

## 10. 数据依赖

已核对 `contracts/public-api/openapi.json` 与 `Generated/OpenAPI/Models.swift`，时间线所需字段服务端**均已具备**，无需改动服务端：

| 需求 | 数据来源 | 客户端现状 |
| --- | --- | --- |
| 任务负责人 | `APITaskDTO.assigned_member_id` | 已映射进 `TaskItem.assignedMemberID`，但 UI 未使用 |
| 变更来源 | `APITaskDTO.changed_by_actor_type`，取值 `account` / `agent` / `system` | **未映射进 `TaskItem`**，需补 |
| 负责人显示名 | `FamilyMember.role.displayName` | 需按 `assignedMemberID == FamilyMember.accountID` 关联 |
| 时间线排序 | 任务 `dueAt`、记录 `occurredAt` | 客户端合并排序 |

唯一缺口是 `TaskItem` 未携带 `changedByActorType`，属客户端映射遗漏，在实施计划的第一个任务补齐。

`assigned_member_id` 与 `FamilyMemberResponse.account_id` 属同一标识空间（`FamilyTaskCountResponse` 即按前者分组、与后者对应）。模板任务的该字段为 `null`，此时任务行不显示负责人段。

## 11. 不在本次范围

- 服务端契约与领域模型改动
- Eve Runtime 的 instructions 与工具改动
- 记录的照片附件
- 产后与育儿期的时间线延展
- Agent 团队与多 Agent 分工的可视化（产品文档 §6 的七个 Agent 在本次仍表现为单一「Aim」）

## 12. 验收标准

1. 时间线在启动后直接定位到今天，用户看不到滚动过程。
2. 过去、今天、未来三段导轨样式可区分，孕周分组头吸顶。
3. 暖色底在有数据与无数据两种状态下一致可见。
4. 深色模式下全部页面文字可读，无白底白字，token 组合满足 AA。
5. Agent 的三档权限分别触发无打断、toast、diff sheet 三种 UI。
6. 应用 Agent 变更后，被改动的任务在时间线上带来源标记，且可通过 toast 或台账撤销。
7. 「让 Agent 分析当前记录」进入后即看到已发起的对话，不再是空输入框。
