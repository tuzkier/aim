# 孕期记录功能设计规格

## 1. 目标

Aim 当前已有“计划”，但缺少记录入口，用户无法沉淀孕期过程中已经发生的事情。本功能增加一个独立的“记录”领域和 iOS 一级入口，让用户记录身体感受、产检结果和其他重要信息，并在确认后把记录转成计划待办。

本次范围只覆盖孕期阶段，不扩展到儿童成长记录；照片附件只保留数据模型扩展位，首个实现不做上传与预览。

## 2. 已确认的产品决策

- 底部导航调整为：今天、计划、记录、家庭、Agent。
- 记录分为三类：`symptom`（身体感受）、`checkup`（产检记录）、`note`（通用记录）。
- 默认记录为家庭共享，也允许创建时选择“仅自己可见”。
- 家庭共享记录对家庭内活跃成员可见；私密记录只有作者可见。
- 身体感受采用结构化标签和程度选择，并允许补充文字。
- 产检记录包含日期、医院、检查项目、结果和医生建议。
- 通用记录包含标题和正文。
- 所有记录都包含发生时间。
- Agent 可以读取当前账号有权限看到的记录，但不能未经确认写入计划。
- “转为待办”必须由用户主动触发或确认 Agent 建议。
- 首个实现先做文字和结构化数据；照片字段预留，不实现文件上传。

## 3. 方案选择

采用独立 `records` 领域，而不是把记录附着在计划任务、孕期事实或 iOS 本地存储上。

独立领域可以保持“发生过什么”和“接下来做什么”的边界，支持家庭权限，并让 Agent 通过明确的只读能力消费记录。记录与计划通过显式的“转为待办”动作连接，不在保存记录时隐式创建任务。

## 4. 领域模型

### 4.1 Record

`Record` 是家庭某个孕期下的一条用户记录。

字段：

- `id: UUID`
- `pregnancy_id: UUID`
- `family_id: UUID`
- `author_account_id: UUID`
- `type: symptom | checkup | note`
- `occurred_at: datetime`
- `visibility: family | private`
- `title: string | null`
- `content: string | null`
- `structured_data: JSON object`
- `attachment_refs: JSON array | null`（预留，首个实现始终为空）
- `created_at: datetime`
- `updated_at: datetime`
- `deleted_at: datetime | null`

`structured_data` 仅承载与类型对应的用户输入，不承载 Agent 推断结果。类型校验在应用层完成：

- `symptom`：`symptoms: string[]`、`severity: 1..5`、可选 `note`
- `checkup`：`hospital`、`exam_items`、`result`、`doctor_advice`
- `note`：可选标题，正文放在 `content`

删除采用软删除，默认查询不返回已删除记录，为后续恢复和审计保留空间。

### 4.2 权限不变量

- 记录必须属于当前账号可访问的家庭和孕期。
- `family` 记录只对同一家庭的活跃成员可见。
- `private` 记录只对作者可见。
- 只有作者可以编辑或删除记录；家庭共享只影响可见性，不改变编辑权限。
- 记录查询、详情和 Agent 工具必须使用同一套可见性过滤规则。

## 5. API 设计

资源前缀为 `/api/v1/pregnancies/{pregnancy_id}/records`。

### 5.1 创建

`POST /api/v1/pregnancies/{pregnancy_id}/records`

请求包含 `type`、`occurred_at`、`visibility` 以及按类型校验的字段。服务端从认证会话取得 `author_account_id` 和 `family_id`，客户端不能覆盖这两个字段。

### 5.2 列表

`GET /api/v1/pregnancies/{pregnancy_id}/records`

默认按 `occurred_at DESC, created_at DESC` 返回当前账号可见的记录；支持按 `type` 筛选。已删除记录不返回。

### 5.3 详情、编辑、删除

- `GET /api/v1/pregnancies/{pregnancy_id}/records/{record_id}`
- `PATCH /api/v1/pregnancies/{pregnancy_id}/records/{record_id}`
- `DELETE /api/v1/pregnancies/{pregnancy_id}/records/{record_id}`

编辑只能修改记录内容、发生时间和可见范围，不能改变所属孕期、家庭或作者。删除只写入 `deleted_at`。

### 5.4 与计划联动

首个实现复用现有计划写入能力，并为任务来源类型增加 `record`。记录详情页的“转为待办”提交一个已有的任务创建请求，`source_id` 指向记录 ID。Agent 建议同样先返回建议，只有用户确认后才调用任务写入能力。

## 6. iOS 交互

### 6.1 RecordsView

- 作为第三个底部 Tab，标题为“记录”。
- 顶部显示最近记录时间线。
- 提供类型筛选：全部、身体感受、产检、通用。
- 无记录时显示空状态和“记录今天的状态”主按钮。
- 右上角 `+` 打开新建记录流程。

### 6.2 RecordComposerView

第一步选择类型，随后显示对应表单：

- 身体感受：标签、程度、补充说明、发生时间
- 产检记录：日期、医院、检查项目、检查结果、医生建议
- 通用记录：标题、正文、发生时间

底部统一提供可见范围选择和保存按钮。表单校验失败时在字段附近提示，不丢失已填写内容。

### 6.3 RecordDetailView

详情页显示记录内容、作者、时间和可见范围，提供：

- 编辑
- 删除
- 转为待办
- 让 Agent 分析当前记录

“转为待办”先打开确认界面，用户确认后才写入计划。
“让 Agent 分析”打开 Agent 并带入当前记录上下文；首个实现不持久化独立的 Agent 建议。

### 6.4 与现有页面的关系

- 今天页继续聚焦当前优先事项，不塞入完整记录表单。
- 计划页继续聚焦未完成/已完成任务，可从任务返回来源记录。
- Agent 页可以引用记录，但不绕过记录页的权限和确认流程。

## 7. Agent 边界

新增记录读取能力，最初只提供：

- 按孕期读取当前账号可见记录
- 按记录类型和时间范围筛选
- 返回原始记录及结构化字段，不把推断写回记录

Agent 读取记录后，可以在对话中给出建议；涉及新增或修改计划时，沿用现有 approval 流程。记录本身的创建、编辑和删除仍由业务 API 负责，不由 Agent 直接执行。

## 8. 错误处理与状态

- 未配置孕期时，记录 Tab 显示引导，不允许提交记录。
- 网络失败时保留表单内容并显示重试入口。
- 权限错误统一显示“这条记录暂时不可见”，不泄露记录是否存在。
- 删除成功后返回列表并显示可恢复空间预留的成功提示。
- 列表为空和加载失败使用不同状态，避免把错误伪装成“暂无记录”。

## 9. 验证计划

### API

- 三类记录的创建与字段校验
- 时间线排序和类型筛选
- 家庭共享/私密记录可见性
- 非作者编辑、删除被拒绝
- 软删除后默认列表不返回
- 记录转待办的来源关联
- OpenAPI 响应与错误契约

### iOS

- Records Tab 加载空状态和时间线
- 三类新建表单保存成功与校验提示
- 可见范围选择
- 编辑、删除和转为待办
- API 失败时表单内容保留

### Agent

- 只能读取当前账号有权限的记录
- 私密记录不会泄漏给家庭其他成员
- 建议写入计划前必须经过用户确认

## 10. 明确不在本次范围

- 照片上传、压缩、预览和对象存储
- 医疗报告 OCR
- 自动诊断或风险分级
- 自动根据每条记录改写整个孕期计划
- 儿童出生后的成长记录
- 跨家庭或跨孕期搜索
