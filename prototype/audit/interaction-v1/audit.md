# 孕期 AI Agent 原型交互审计

## 总体结论

视觉风格已经接近确认方向，但产品交互仍是页面级演示，尚未形成可信的家庭计划闭环。最严重的问题是 Agent 输入焦点跨页面残留；最关键的产品问题是任务、Agent 变更和家庭分工没有共享同一套可追踪状态。

## 流程步骤

1. Today 起点 — 一般：能看见优先事项，但缺少优先原因、快捷调整和下一步状态。
2. 任务详情 — 较弱：信息可读，但“已安排”含义不清，且不能改时间、延期或重新分配。
3. 完成反馈 — 不健康：完成后旧任务仍占据“今天最重要”；导航返回期间出现键盘与滚动错位。
4. Agent 输入 — 不健康：输入框焦点和模拟键盘跨 Tab 残留，页面被挤到错误位置。
5. Agent 结果 — 较弱：系统直接提交计划变化，没有理解确认、变更预览、权限提示和撤销。
6. 计划同步 — 不健康：计划数据虽然变化，但页面停在中段且键盘遮挡，用户无法确认整体影响。
7. 家庭协作 — 较弱：成员可见，但任务分配不能在这里或任务详情中闭环，邀请也没有改变成员状态。

## 证据与问题

### P0 — 输入焦点跨页面泄漏

- 证据：`04-agent-input.png`、`06-plan-after-agent.png`、`07-family.png`
- 现象：进入 Agent 后，即使没有主动聚焦输入框，模拟键盘仍会出现；切换计划或家庭后键盘持续遮挡，页面保留错误滚动位置。
- 影响：主导航不能可靠使用，用户可能误以为页面内容丢失。
- 修正：移除 Agent 页常驻输入框，将文本输入放入 BottomSheet；关闭或切换页面时同步释放焦点与键盘状态。

### P1 — 任务没有生命周期

- 证据：`02-task-detail.png`、`03-after-complete.png`
- 现象：“预约检查”只能被标记为“已安排”，但界面没有记录预约日期，也不区分待处理、已预约、已完成；返回后它仍是第一优先。
- 影响：Today 不能回答“接下来该做什么”，计划也无法基于真实进度推进。
- 修正：引入 `待处理 / 已安排 / 已完成` 状态；安排后记录日期，将材料准备提升为下一优先，并提供撤销。

### P1 — Agent 直接写入，无确认和撤销

- 证据：`04-agent-input.png`、`05-agent-result.png`
- 现象：点击建议并发送后，Agent 直接修改检查日期和准备任务。
- 影响：用户无法确认 Agent 是否理解正确，也不能控制它修改了哪些家庭事实和任务。
- 修正：改为“我理解的是 → 将产生的变更 → 应用变更”；应用后展示变更来源和撤销操作。

### P1 — 家庭协作未进入任务闭环

- 证据：`02-task-detail.png`、`07-family.png`
- 现象：任务负责人只是文本，不能在任务详情重新分配；成员邀请成功也不会改变家庭列表。
- 影响：爸爸/妈妈是展示身份，而不是可执行的协作者。
- 修正：任务详情支持重新分配；家庭页展示每人待办数和最近同步；邀请后出现“等待加入”成员。

### P2 — 操作语义和反馈不足

- 证据：`01-today.png`、`02-task-detail.png`
- 现象：“查看准备事项”和“标记为已安排”跨度过大；准备清单里默认勾选一项但没有来源和解释。
- 影响：用户不确定按钮会执行什么，也无法区分查看、确认、预约和完成。
- 修正：主按钮使用动作语义；任务详情提供明确的预约、调整、分配入口，并显示 Agent/用户变更来源。

## 可访问性风险

- 多处次级文本对比度偏低，需要在最终 SwiftUI 实现中以系统动态颜色复核。
- 圆形完成按钮依赖形状表达状态，需保留明确的 VoiceOver 标签。
- 截图无法验证动态字体、VoiceOver 顺序、减少动态效果和键盘焦点恢复；这些必须在正式 iOS 工程中测试。
